# 电子签章（e签宝）接入手册

> 配套技术方案：`doc/esign/电子签章集成技术方案.md`（设计、口径、代码位置）
> 本手册只讲**怎么配、怎么跑通、怎么排查**。

---

## 0. 一分钟总览

| 项 | 内容 |
| --- | --- |
| 能力 | 公文定稿/签章节点自动用印；两种方案并存可切换（自研 CA / 第三方 e签宝） |
| 第三方 | e签宝 SaaS API V3（沙箱 `https://smlopenapi.esign.cn`，生产 `https://openapi.esign.cn`） |
| 配置入口 | 前端「公文通用设置」`/odoc/setting` → 「电子签章方案」 |
| 流程配置 | 「流程建文设置」弹窗 → 「用印位置与签署方」 |
| 关键约束 | 第三方密钥只在 Nacos；回调路径必须在 `xss.skip-url` + `secure.skip-url` 白名单里 |

## 1. 前置准备

1. **e签宝账号**：沙箱环境需在 e签宝开放平台注册应用，拿到 `appId` / `appSecret`，
   并完成机构（orgId）认证、创建测试印章、添加测试签署人（手机号/实名）。
2. **回调地址可达**：`{对外域名}/api/blade-workflow/odoc/esign/callback` 必须能被 e签宝外网访问
   （内网 dev 环境需做公网映射/隧道，否则回调永远收不到）。
3. **依赖版本**：本项目 `odoc.esign.*` 走**根级 `odoc:`** 配置（不是 `blade.workflow.odoc`）。

## 2. 数据库迁移

按顺序执行（幂等，可重复跑）：

```
doc/sql/migration/V2026.10.25_001__wf_odoc_esign.sql            -- 新建 3 张签章表
doc/sql/migration/V2026.10.25_002__wf_odoc_esign_base_cols.sql   -- 补公共列 + 业务状态列改名
doc/sql/migration/V2026.10.25_003__wf_odoc_setting_seal_mode.sql -- 设置表加签章方案列
```

校验：

```sql
-- 三张表存在且列齐全
SELECT TABLE_NAME, COUNT(*) FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'blade' AND TABLE_NAME LIKE 'wf_odoc_sign_%'
GROUP BY TABLE_NAME;

-- 公共设置表的签章方案列
SELECT id, seal_mode, seal_esign_org_id, seal_esign_default_seal_id, seal_esign_notify_url
FROM wf_odoc_setting;
```

> ⚠️ 新建的表继承 `TenantEntity`，**必须包含** `id/create_user/create_dept/create_time/update_user/update_time/status/is_deleted/tenant_id`，
> 缺列会直接报 `Unknown column`。业务状态另起列名（`sign_status`），不要占用公共 `status`。

## 3. Nacos 配置（运维级/敏感）

在 `blade-dev.yaml`（生产 `blade-prod.yaml`）**根级** `odoc:` 下：

```yaml
odoc:
  esign:
    enabled: true
    host: https://smlopenapi.esign.cn     # 生产：https://openapi.esign.cn
    sandbox: true
    app-id: ${ESIGN_APP_ID}               # 敏感
    app-secret: ${ESIGN_APP_SECRET}       # 敏感
    org-id: ${ESIGN_ORG_ID}
    notify-url: https://{对外域名}/api/blade-workflow/odoc/esign/callback
    timeout-ms: 10000
    sign:
      charge-mode: 0
      notice-types: "1"                   # 短信通知
      auto-sign-platform: true            # 平台自动落章
    seal:
      mode: local                         # 兜底值，实际以业务表 wf_odoc_setting.seal_mode 为准
      default-seal-id: ""
    compensate:
      enabled: true
      cron: "0 */5 * * * ?"
      max-hours: 72
    archive:
      format: pdf                         # pdf / ofd
```

**必须同时加白名单**（否则回调全丢）：

```yaml
blade:
  xss:
    skip-url:
      - /odoc/esign/**      # 报文参与 HMAC 验签，被 XSS 过滤器改写必然验签失败
  secure:
    skip-url:
      - /odoc/esign/callback # 厂商外网直连、无 token，网关放行
```

> 改完 Nacos **需要重启 blade-workflow**（白名单与配置在启动时读取）。

## 4. 编译与部署

```bash
mvn -pl blade-service/blade-workflow -am compile -DskipTests
mvn -pl blade-service/blade-workflow -am install -DskipTests
```

> ⚠️ 本地仓库一致性：springBlade 的 `.mvn/maven.config` 指向 `E:\project\mavenLib`，与 `blade-tool`
> 的安装仓库一致（core/starter 装进同一仓库才能被本工程读到）。
> 若报 `Could not find artifact org.flowable:flowable-engine:8.1.0-SNAPSHOT` 或
> `程序包 org.springblade.core.boot.file.service 不存在`，先在 `D:\workproject\blade-tool`
> 跑 `mvn clean install`，再在本工程构建（可加 `-Dmaven.legacyLocalRepo=true` 忽略来源标记）。

启动（dev：网关 81、auth 8100、system 8106、**blade-workflow 8111**、前端 8000）：

```bash
mvn -o -pl blade-service/blade-workflow spring-boot:run
```

启动后自检：

```bash
curl -s "http://127.0.0.1:8111/odoc/setting/seal" -H "Blade-Auth: <token>"
# 期望：{"code":200,"data":{"sealMode":0,"vendor":"local","esignEnabled":true,"esignReady":true,...}}
```

## 5. 前端配置（三步）

### 5.1 选签章方案
「公文通用设置」`http://<host>:8000/odoc/setting` → 「电子签章方案」卡片：

1. 选「第三方电子签章（e签宝）」；
2. 填**第三方机构ID**（orgId）、**默认印章**（可从印章库下拉选，也可手填 sealId）、**签署回调地址**；
3. 保存。页面顶部会显示接入状态（总开关 / 域名 / appId 掩码 / 是否就绪）。

> 方案选择落业务表 `wf_odoc_setting.seal_mode`，**业务表优先、Nacos 兜底**；密钥永远不在页面维护。

### 5.2 流程建文设置
流程设计器 → 「流程建文设置」弹窗：

1. 「签章节点」选到用印节点（多选用「签章节点（多选）」）；
2. 勾「必须电子签章」；
3. 「用印位置与签署方」：填页码/X(mm)/Y(mm)/章型，并**添加签署方**
   （个人：手机号+姓名+证件号；企业：企业名称+统一信用代码；可指定印章ID、是否自动落章）。

> 第三方方案下**必须配置签署方**，否则流程会跳过用印并打告警日志（不阻塞审批）。

### 5.3 版式文件
用印前正文需已有 **PDF(12)/OFD(13) 版式文件**：流程的「转版式节点」会自动转，
也可在公文区「版式 / 电子签章（L2）」面板手动点「转 PDF」。

## 6. 端到端验证

1. 走到签章节点 → 提交；
2. 日志出现 `用印发起完成. instId=..., mode=esign, finished=false, flowId=...`；
3. 数据库：

```sql
SELECT id, doc_id, esign_file_id, flow_id, biz_num, seal_mode, sign_status, notify_count
FROM wf_odoc_sign_flow ORDER BY id DESC LIMIT 5;

SELECT id, flow_id, signer_type, sign_order, account_name, auto_sign, sign_status, sign_url
FROM wf_odoc_sign_signer ORDER BY id DESC LIMIT 5;
```

4. 签署方在公文区点「去签署」→ 完成签署；
5. 收到回调后：

```sql
SELECT esign_flow_id, action, sign_result, processed, process_msg, receive_time
FROM wf_odoc_sign_notify ORDER BY id DESC LIMIT 10;
-- processed=1 已处理；sign_result=2 签署完成

SELECT id, doc_id, archive_version_id, sign_status FROM wf_odoc_sign_flow ORDER BY id DESC LIMIT 1;
-- sign_status=2 已完成；archive_version_id 指向归档后的公文版本

SELECT id, version_id, file_name, doc_file_type, version_detail
FROM wf_odoc_doc_version WHERE doc_id = <docId> ORDER BY id DESC LIMIT 5;
-- 新增一条「电子签章归档件」（doc_file_type 12=pdf / 13=ofd）
```

6. 前端刷新 → 公文区显示「已签署 / 签署件已归档」，当前版本即签署件。

> **「签完才流转」（2026-10-25 改造后）**：提交签章节点时**流程不再立即流转**，而是停在签章节点等签署完成；
> 厂商回调（或补偿任务）确认签署完成后，由 `OdocSealAdvancer` 推进引擎任务并流转到下一节点。
> 校验点：`wf_odoc_sign_flow.advance_status`（0待推进 1推进中 2已推进 3已终止），
> 拒签/超时会置 3 并把业务待办恢复为待办（办理人可重新提交，进入新一轮签署）。

```bash
cd doc/esign

python esign_sandbox_test.py callback      # 本地回调验签自测：先错误签名（应失败），再正确签名（应 SUCCESS）
python esign_sandbox_test.py seals         # 印章列表（需真实 app-id/app-secret/org-id）
python esign_sandbox_test.py full          # 全链路：上传→创建签署流程→启动→查详情（需真实凭据 + sample.pdf）
```

凭据来源优先级：环境变量 `ESIGN_APP_ID` / `ESIGN_APP_SECRET` / `ESIGN_ORG_ID` > Nacos `blade-workflow-dev.yaml` 的 `odoc.esign.*`。

**回调自测的预期日志**（`C:\wfobs\wf_esign.log`）：

```
[esign] 回调验签失败 flowId=... action=SIGN_FLOW              # 错误签名
```

**运维辅助脚本**（同目录）：`_restart_wf.ps1`（停旧实例→重新打包→重启 blade-workflow）、`_loggrep.ps1`（按关键字 grep 日志）。

## 7. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| 回调收不到 | 网关/服务白名单未加（`secure.skip-url`）；回调地址不可外网访问；厂商未配置 notify-url |
| 回调到了但 `processed=2` | 验签失败：检查 `xss.skip-url` 是否含 `/odoc/esign/**`（报文被清洗 → 签名必失）；再核对 appSecret 与拼接口径 |
| 发起用印报「未就绪」 | `odoc.esign.enabled/app-id/app-secret` 未配齐；或当前方案指向的策略 `available=false`（策略不可用即报错，不静默降级） |
| 发起用印报「缺少待签文件」 | 正文还没有 PDF/OFD 版式文件，先转版式 |
| 发起用印无反应（只有告警） | 流程设置里没配签署方（`seal_config.signers`）；或该正文已有进行中的签署流程（幂等跳过） |
| 提交被拦「必须先生成版式文件」 | 第三方方案下的提交前校验：需先出版式文件 |
| 提交被拦「必须完成电子签章」 | 自研方案下的原有校验：需已有成功签章记录 |
| 流程没等签署就流转了 | 若是**旧版本**行为（提交即流转）则属改造前逻辑；改造后应停在签章节点，查 `wf_odoc_sign_flow.advance_status` 与回调/补偿日志 |
| 流程卡在签章节点不流转 | 签署未完成（查 `wf_odoc_sign_flow.sign_status` 与厂商签署方状态）；或回调没到（白名单/notify-url）；或推进失败（查 `advance_msg`，补偿任务会重试） |
| 回调日志「重复投递已忽略」 | 上一轮该事件已 `processed=1`（正常幂等）；若是「上次失败」的事件，重投会被允许重试（`processed=2` → 更新报文继续处理） |
| 厂商报「无效的应用」/401 | `odoc.esign.app-id`/`app-secret` 与厂商沙箱账号不匹配（占位值必然 401），换真实凭据后重试 |
| 归档没产生 | 回调/补偿未拿到「签署完成」状态；查 `wf_odoc_sign_flow.last_query_time` 与补偿任务日志 |

## 8. 生产上线检查项

- [ ] 密钥与沙箱**完全分离**，用生产密钥调一次简单接口验证（官方明确要求）；
- [ ] **涉密公文**复核：若涉密公文需走涉密环境，须切混合云「天印」/私有化（当前实现只走公有云 SaaS）；
- [ ] 回调地址为**公网可达**且走 HTTPS；
- [ ] `blade.xss.skip-url`、`blade.secure.skip-url` 已发布到 Nacos；
- [ ] 归档件与原文**双版本留存**策略确认（`odoc.esign.archive.keep-source-version`）；
- [ ] 补偿任务开启（`compensate.enabled=true`，默认 5 分钟一轮，超 72 小时置「已过期」）；
- [ ] 监控：`wf_odoc_sign_flow` 中 `sign_status` 长期为 1（进行中）/`notify_count` 为 0 的记录；
- [ ] 归档目录容量与签章件下载失败告警。
