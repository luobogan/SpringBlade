## 0. 采集说明（重要）

按需求使用 Playwright MCP Server 访问页面，实际结果：

| 步骤 | 结果 |
| --- | --- |
| `playwright_navigate` → `http://127.0.0.1:8000/formmode/workflowdesign` | 导航成功 |

## 1. 页面结构与字段分布

「流转设置」是三个平级页签：`图形编辑` / `节点信息` / `出口信息`（`WorkflowDesign.tsx:428-470`），默认停在 `canvas`。
「节点信息」（`NodeInfoPanel.tsx`）由**上、中、下三段**组成：

```
┌─ 头部工具条 ────────────────────────────────────────────┐
│ 当前节点：<名称> <类型Tag>   [编辑节点] [定位到画布]        │
├─ NodeInfoTable 可编辑宽表（13 列 + 操作列）────────────────┤
│ 节点名称│节点类型│操作者│表单内容│操作菜单│节点前附加操作│   │
│ 节点后附加操作│子流程设置│标题显示设置│签字意见设置│        │
│ 流程异常处理│表单日志查看范围│指定流转│操作              │   │
│ [+ 新增节点]（表尾草稿行）                                │
├─ Card「节点详情：xxx」（仅选中节点时）────────────────────┤
│  Tabs：基本属性 / 操作者 / 字段权限 / 节点设置 / 表单布局   │
└─────────────────────────────────────────────────────────┘
```

- 上、中段由 `NodeInfoTable.tsx` 实现（一行一个节点，**即改即存**）；
- 下段由 `NodeDetail.tsx` 实现（当前选中节点的纵向详情，五个页签）；
- 两段的设置类字段共用同一份 schema：`nodeSettings.ts` 的 `SETTING_DEFS`。

## 2. 表格列字段（NodeInfoTable，13 列）

### 2.1 节点名称

| 项 | 内容 |
| --- | --- |
| **含义** | 节点在流程图与待办中显示的名称 |
| **用途** | 画布标签、待办标题、出口「目标节点」下拉的显示文本 |
| **可能取值** | 任意字符串（必填，`NodeDetail` 表单 `required`；E9 校验非空，历史版本限 60 字符） |
| **来源/关联位置** | 前端：`NodeInfoTable.tsx:183-213`（列）/ `NodeDetail.tsx:297-299`（表单项）；后端：`WfProcessNode.nodeName`；E9：`workflow_nodebase.nodename` |

- **前端展示逻辑**：单元格为 `Input`，使用 `draft` 草稿态（`${nodeKey}|nodeName`），**失焦或回车才提交**，避免每敲一键发一次请求；提交后额外调用 `onRename` → 父级 `renameEvt` 回写画布节点标签（画布几何/标签由 BPMN 承载，必须双向同步）。草稿行（`_draft`）时该列为「新节点名称」输入框。
- **后端处理逻辑**：`PUT /blade-workflow/definition/{id}/node/{nodeKey}`（`WfDefinitionController.updateNode`），按 `defId + nodeKey` 局部 merge 更新 `wf_process_node.node_name`；返回更新后的实体，前端 `onPatch` 就地替换列表数据。

### 2.2 节点类型

| 项 | 内容 |
| --- | --- |
| **含义** | 节点在工作流中的语义角色 |
| **用途** | 决定是否有操作者、是否可退回、是否触发子流程/超时、部署时映射为 BPMN 任务类型 |
| **可能取值** | `0 创建 / 1 审批 / 2 提交 / 3 归档 / 5 等待 / 6 自动处理`（`wfDict.NODE_TYPES`）；E9 为 `0创建 1审批 2处理 3归档` |
| **来源/关联位置** | 前端：`NodeInfoTable.tsx:214-237`、`wfDict.ts:15-22`；后端 SQL 注释 `doc/sql/workflow-schema.sql:79`；E9：`NodeInfo.js:582-604`（切换类型会改画布形状与图标） |

- **前端展示逻辑**：`Select`，`onChange` 即提交。草稿行默认 `1 审批`。
- **后端处理逻辑**：写 `wf_process_node.node_type`。⚠️ 注意画布侧约束：`saveBpmn` 只把 `StartEvent→0 / UserTask→1 / EndEvent→3` 解析成节点，因此 `2/5/6` 这类特殊类型在画布批量新增后需要再发一次 `updateNode` 回写真实类型（`WorkflowDesign.handleNodesCreated`）。

### 2.3 操作者

| 项 | 内容 |
| --- | --- |
| **含义** | 该节点由谁处理（多人时为操作组） |
| **用途** | 运行时生成待办、计算会签/或签、决定转办/加签对象 |
| **可能取值** | 多条记录，每条含 **类型 / 对象 / 范围 / 批次**（见下表） |
| **来源/关联位置** | 前端：`NodeInfoTable.tsx:238-254` + `NodeOperatorModal.tsx` / `NodeDetail.tsx:334-436`；后端：`WfNodeOperator`、`wf_node_operator`；E9：`workflow_groupdetail`（`NodeInfo.js:379-388`，设置页 `pathSet/operatorSet`） |

操作者行字段：

| 子字段 | 取值 | 含义 |
| --- | --- | --- |
| 类型 `opType` | `3人员 / 1部门 / 2角色 / 58岗位 / 4所有人 / 17创建人本人 / 18创建人上级 / 19本部门`（`wfDict.OP_TYPES`；表结构注释另含 30分部 / 40本人 / 41上级 / 5字段-人员 / 6字段-人员上级 / 42字段-部门 / 43字段-角色 / 99矩阵 / 97接口 / 98SQL） | 操作者对象类别，对齐 E9 `OperatorDBType` |
| 对象 / 字段 `objId` | 人员/部门/角色/岗位 ID，或表单字段名（动态操作者） | 具体对象 |
| 范围 `bhxj` | `0本部 / 1含下级 / 2含上级 / 3逐级向上` | 组织范围收敛方式 |
| 批次 `batchNo` | ≥0 整数 | 依次审批时的顺序号（对齐 E9 `ORDERS`） |
| （表结构还有）`groupNo / levelMin / levelMax / signOrder / conditionJson` | — | 操作组序号、安全级别上下限、组内会签关系、生效条件（当前弹窗未暴露） |

- **前端展示逻辑**：单元格只显示「N 项 / 未设置」+「编辑」；点击打开 `NodeOperatorModal`（或 `NodeDetail` 的「操作者」页签内联表格），可增删行、改四列。列表按 `keysKey`（所有 nodeKey 拼接）做依赖，加载一次后不再随单元格刷新重拉。
- **后端处理逻辑**：`PUT /definition/{id}/node/{nodeKey}/operator`，**整体覆盖**写 `wf_node_operator`（先删该节点旧记录再批量插入）。⚠️ 请求体必须是 `{ operators: [...] }` 实体包装（`NodeOperatorSaveDTO`），**不能发裸数组**——本环境 `@RequestBody` 根类型为泛型容器会丢泛型，导致 `LinkedHashMap` 反序列化失败。

### 2.12 表单日志查看范围

| 项 | 内容 |
| --- | --- |
| **含义** | 该节点的操作者可查看哪些表单修改日志 |
| **子字段取值** | `scope`：`all 全部` / `node 仅本节点` / `self 仅本人` |
| **来源/关联位置** | 前端：`nodeSettings.ts:82-97`；E9：`formLogViewRange` → `workflow_flownode.viewnodeids`（`hasLogViewSco`，`LayoutDataBiz.java:414-420`），设置页 `pathSet/formLog` |

## 6. 「节点信息」与「画布（BpmnDesigner）」的关联机制（本系统）

### 6.1 关联的本质：`nodeKey` 是唯一纽带

| 概念 | 画布侧（bpmn-js） | 节点信息侧（表格/详情） | 绑定点 |
| --- | --- | --- | --- |
| 节点身份 | BPMN 元素 `id`（如 `UserTask_abc123`） | `wf_process_node.node_key` | **同一个字符串** |
| 生成时机 | 用户从图形库拖入 / 批量生成时 `genId()` 生成 | 后端 `saveBpmn` 解析 XML 时写入 | `WfDefinitionServiceImpl:223` `String key = fe.getId();` |
| 表格主键 | — | `rowKey={(r) => String(r.nodeKey)}` | `NodeInfoTable.tsx:395` |
| 详情定位 | `elementRegistry.get(nodeKey)` | `nodes.find(n => n.nodeKey === selectedNodeKey)` | `NodeInfoPanel.tsx:58-61`、`BpmnDesigner.tsx:397` |

> 结论：**画布元素 id 就是节点信息的主键**。二者没有中间映射表，也没有冗余的"图形表"——节点表不存坐标，坐标只存在于 BPMN 的 DI 段。

### 6.2 五条联动通道（状态与事件）

```
                        ┌────────────── WorkflowDesign.tsx（唯一状态中枢）──────────────┐
                        │  nodes / links / bpmn / selectedNodeKey                       │
                        │  renameEvt / focusEvt / createNodesEvt / linkCmd              │
                        └───────┬───────────────────────────────────────────┬───────────┘
        ① onSelectNode(k)       │                                           │  nodes / selectedNodeKey
           （选中同步，不切页签）│                                           │
                        ┌───────▼────────┐                         ┌────────▼─────────┐
                        │  BpmnDesigner  │◄──── ② renameEvt ───────│  NodeInfoPanel   │
                        │   （画布）      │◄──── ③ focusEvt ────────│  NodeInfoTable   │
                        │                │◄──── ④ createNodesEvt ──│  NodeDetail      │
                        └───────┬────────┘                         └──────────────────┘
                                │ ⑤ onSaved → refreshNodes()/refreshLinks()
                                └────► 后端 saveBpmn → upsert wf_process_node / wf_node_link
```

| --- | --- | --- | --- | --- |
| ① | 画布 → 节点信息 | `onSelectNode(k)` → `selectedNodeKey` | 点画布上的节点/连线 | `BpmnDesigner.tsx:264-279` → `WorkflowDesign.tsx:369` → `NodeInfoPanel` |

### 6.3 通道详解

#### ① 画布选中 → 节点信息（`selection.changed`）

- **事件源**：bpmn-js 原生 `eventBus.on('selection.changed')`，**不是**自定义 overlay 点击（画布上的 ≡/➤ 图标与热区已于 2026-09-11 移除）。
- **形状解析（关键坑）**：选中一个形状时 bpmn-js 会把**标签元素**一并放入 `newSelection`，其 id 为 `${id}_label`，与 `node_key` 对不上 → 必须过滤：
  ```ts
  const shape = list.find(x => !x.labelTarget && isNodeElement(x));
  ```
  `isNodeElement` 只认 `bpmn:StartEvent / bpmn:UserTask / bpmn:EndEvent`（`BpmnDesigner.tsx:97-100`），因此**选中网关/子流程/连线不会驱动节点信息**。
- **只读态能选中的前提**：`bpmnDesigner.css` 中 `.djs-container *{pointer-events:none}`，例外放开 `.djs-element*`（auto）；编辑类命令由 `commandStack.<action>.canExecute` 监听（优先级 2000）在只读态返回 `false` 阻断，选中不受影响。
- **不切页签**：`onSelectNode` 只 `setSelectedNodeKey(k)`，明确**不**执行 `setFlowSubTab('node')`（编辑态下频繁选中若被弹走就无法连续建模）。用户需要自己点「节点信息」页签。
- **反向不成立**：在节点信息表格里**点行**只会 `onSelect` 改 `selectedNodeKey`（行高亮 `wf-row-active` + 下方详情卡切换），**不会**让画布选中该元素；只有点「定位」才会真正在画布上 `selection.select(el)`。

#### ② 改名回写画布（`renameEvt`）

- 链路：`updateNode`（写库）成功 → `onSaved(nodeKey, name)` → `setRenameEvt({seq, nodeKey, name})` → 画布
  `elementRegistry.get(nodeKey)` → `modeling.updateProperties(el, { name })`（走 commandStack，可撤销）。
- `seq` 用 `Date.now()`，effect 依赖 `[renameNode?.seq]`（重名连续改两次也能触发）。
- **为何必须回写**：后端 `saveBpmn` 对已存在节点执行的是
  ```java
  exist.setNodeName(nodeName);  // nodeName = defaultNodeName(fe, nodeType)，优先取 BPMN 的 fe.getName()
  exist.setSortOrder(sort++);
  nodeMapper.updateById(exist); // 只改这两个字段
  ```
  即**画布名称是节点名的权威来源**。若只改库不回写画布，下次保存画布时节点名会被 BPMN 里的旧名字覆盖回去（表现为"改名后又变回去"）。

#### ③ 定位并高亮（`focusEvt`）

`locateNode` 三步：`setActiveTab('flow')` → `setFlowSubTab('canvas')` → `setFocusEvt({seq:Date.now(), nodeKey})`。

画布侧执行（`BpmnDesigner.tsx:443-498`），带**重试**（最多 10×200ms，应对画布刚从 `display:none` 切回 / 懒加载未就绪 / XML 未导入完）：

1. `canvas.resized()` —— 隐藏期间容器尺寸为 0，不修正会算错坐标；
2. `registry.get(nodeKey)` 取元素；
3. `selection.select(el)` + `canvas.scrollToElement(el)`；
4. `canvas.addMarker(el, 'wf-flash')`，2s 后移除（`.wf-flash` 描边脉冲动画，`bpmnDesigner.css`）。

#### ④ 新增节点（`createNodesEvt`）

**"节点信息里新增"必须落到画布**，因为节点表不存几何、且节点的"存在性"由画布决定。

- 父级用**自增计数器** `createSeqRef` 生成 seq（不能用 `Date.now()`：同一毫秒内 seq 不变 → effect 不重跑 → 第二次点击无反应）；画布侧用 `lastCreateSeqRef` 保证同一 seq 只执行一次。
- 画布执行顺序（`BpmnDesigner.tsx:517-620`）：
  1. **先** `editModeRef.current = true; setEditMode(true)` —— 否则展示态的 `canExecute` 拦截会把 `shape.create / connection.create` **静默吃掉**（不报错但形状建不出来）；
  2. 找追加锚点（无出线的 UserTask → 否则 Start → 都没有就先造 Start）；
  3. 逐个 `moddle.create` + `elementFactory.createShape` + `modeling.createShape` + `modeling.connect(prev, shape)`，横向排成链；
  4. 末尾接 End（存在则重接，不存在则新建并连接）；
  5. `handleSave()` 自动保存 → 成功后 `onNodesCreated(created)`。
- 类型映射（`shapeTypeFor`）：画布只认 3 种形状，其余落到 `UserTask`：
  | 期望 nodeType | 画布形状 | 说明 |
  | --- | --- | --- |
  | 0 创建 | `bpmn:StartEvent`（仅当尚无 Start） | 否则降级 UserTask |
  | 1 审批 | `bpmn:UserTask` | |
  | 2 提交 / 5 等待 / 6 自动 | `bpmn:UserTask` | 保存后由 `handleNodesCreated` 用 `updateNode` 回写真实类型 |
  | 3 归档 | `bpmn:EndEvent`（仅当尚无 End） | 否则降级 UserTask |
- 父级 `handleNodesCreated`：对 `nodeType ∉ {0,1,3}` 的节点发 `updateNode({nodeType})`，然后 `refreshNodes() + refreshLinks()`。

#### ⑤ 画布保存 → 节点表同步（`saveBpmn`）

前端：`handleSave()` → `modeler.saveXML({format:true})` → `PUT /definition/{id}/bpmn`(`BpmnSaveDTO{bpmnXml}`) → 成功调 `onSaved` → `refreshNodes()/refreshLinks()` 重拉列表。

| 步骤 | 行为 |
| --- | --- |
| 解析 | `BpmnXMLConverter` → `model.getMainProcess()`；`process.getId()` 回写 `def.procKey`（画布 process id 为准） |
| 节点 upsert | 按 `fe.getId()` 匹配既有 `node_key`；**命中**：只更新 `node_name` + `sort_order`；**未命中**：新增（类型由 `nodeTypeOf` 给出 0/1/3，`sign_order=0`） |

### 6.4 职责边界：谁是权威来源

| 数据 | 权威来源 | 说明 |
| --- | --- | --- |
| 节点**是否存在**、节点**数量** | **画布**（BPMN） | `saveBpmn` 会删除画布上没有的节点 |
| 节点**坐标 / 尺寸 / 连线走向 / 网关分支** | **画布**（BPMN DI） | 节点表无几何字段，只能改画布 |
| 节点**名称** | **画布优先**（保存时以 `fe.getName()` 覆盖） | 故改名必须走 `renameEvt` 双向同步 |
| 节点**类型** 2/5/6 | **节点表** | 画布只区分 0/1/3，特殊类型由前端回写 |
| 审批方式 / 合并类型 / 合并阈值 / 允许退回·转办·自动批准 / `ext_json` | **节点表** | `saveBpmn` 明确不动这些字段 |
| 操作者 / 字段权限 | **节点表**（`wf_node_operator`、`wf_node_field_perm`） | 但节点的删除会连带删除 |
| 出口**存在性** | **画布**；出口**条件/退回/必经** | **节点表**（upsert 时保留） |

一句话：**画布管结构（有谁、连谁、在哪），节点信息管语义（谁审批、怎么审批、看什么、能干什么）**。

### 6.5 已知约束与风险

1. **改名必须回写画布**：只写库不回写 → 下次保存画布被 `defaultNodeName` 覆盖回滚（见 6.3②）。
2. **`createNodesEvt` 依赖画布已挂载**：默认 `flowSubTab='canvas'` 且 rc-tabs 保持挂载（切走仅 `display:none`），modeler 一定存在；若把默认页签改为 `node` 且不加 `forceRender`，内联新增会失效。
3. **画布页签禁止 `forceRender`**：非激活页签挂载会以 0 尺寸渲染，`zoom('fit-viewport')` 会算错；尺寸修正依赖 `ResizeObserver` + `canvas.resized()`。
4. **批量新增必须先切编辑态**：只读态的 `canExecute` 拦截会让建模命令静默失败。
5. **元素 id 变更 = 换节点**：导入新 XML / 手工改 id 后 `node_key` 变化 → 旧节点被 `saveBpmn` 判为"画布上不存在"而删除，随之删除其操作者。
6. ✅ **字段权限孤儿已修**（v1.1）：`saveBpmn` 删除节点时已补删 `wf_node_field_perm` 与 `wf_node_detail_perm`（见 `WfDefinitionServiceImpl`），不再是风险项。
7. ✅ **保存画布后重置选中**（v1.1）：`WorkflowDesign` 的 BpmnDesigner `onSaved` 已顺手 `setSelectedNodeKey(undefined)`，避免选中态指向已删除节点。

### 6.6 与 E9 的对比

E9 中「节点信息」与图形编辑器是**同构**的：图形（mxGraph cell）与节点（`workflow_flownode` / `workflow_nodebase`）通过 `nodeId` 关联，且**节点属性（坐标 `drawxpos/drawypos`、nodeattribute、nodetype）直接存在 `workflow_flownode` 表里**（`LayoutDataBiz.java:427` 读 `drawxpos/drawypos`），即"图形表 = 节点表"。

本系统是**异构**的：图形在 BPMN XML（`wf_process_definition.bpmn_xml`），语义在 `wf_process_node`，靠 `nodeKey == 元素 id` 关联。差异带来的直接后果就是 6.5 中的 1/5/6 三条约束。

### 7.6 权威来源：E9 是「画布单向权威」

E9 与本系统最大的理念差异：**E9 的节点表本身就是"图形表"**。

| 数据 | E9 权威来源 | 说明 |
| --- | --- | --- |
| 节点存在性 / 坐标 / 尺寸 | **画布 cell** | 坐标最终写进 `workflow_nodebase.drawxpos/drawypos`（`LayoutDataBiz:738`） |
| 节点名称 | **画布 cell.value** | `model.setValue` 改 cell → 保存时随 XML `value` 属性入库（`XML_ATTRIBUTE_VALUE` → `workflowNode.name` → `nodename`） |
| 节点类型 / 节点属性 / 通过分支数 | **画布 cell**（cell.nodeType / nodeAttriBute / passnum / targetBranchValue） | 面板里「类型」「合并类型」直接改 cell（`NodeInfo.js:582-716`） |
| 新增 / 删除 | **画布** | 面板无新增删除入口；删除 = 画布删 cell + 保存时 diff |
| 操作者 / 操作菜单 / 前后附加 / 签字意见 / 超时 / 子流程 / 指定流转 / 日志范围 | **各自的业务表**（`workflow_groupdetail`、`workflow_nodecustomrcmenu`、`workflow_addinoperate`、`workflow_flownode`、`workflow_nodeOverTime` …） | 面板只是**入口 + 打勾状态**（`nodeDatas[nodeId][key]`），详情由独立页面（`/api/.../pathSet/xxx`）保存 |

由此产生两条 E9 特有的行为：

1. **改名不会被回滚**：一次 `model.setValue` 同时改了 cell 与（保存后的）库，不存在"库改了画布没改"的中间态；
2. **设置项会反向影响画布**：前/后附加操作配置后，画布节点上会直接多出 `icon-workflow-caozuoqian`（操作前）/ `icon-workflow-caozuohou`（操作后）角标——这是"节点信息 → 画布"的可见回写（本系统没有对应机制）。

### 7.7 E9 与本系统对照

| 维度 | E9 | 本系统（SpringBlade） |
| --- | --- | --- |
| 画布技术 | mxGraph + 私有 XML schema | bpmn-js + BPMN 2.0 |
| 纽带 | `cell.nodeId` / `cell.linkId`（自定义属性） | `nodeKey` == BPMN 元素 id |
| 图形持久化 | 设计器 XML（Base64）→ 解析写 `workflow_flownode / workflow_nodebase`（**坐标在节点表**） | `wf_process_definition.bpmn_xml`（**节点表无坐标**） |
| 结构 vs 语义 | **同构**（节点表即图形表） | **异构**（结构在 XML，语义在节点表） |
| 改名 | `model.setValue(cell)`，无回滚风险 | 写库 + `renameEvt` 回写，漏回写会被覆盖 |
| 新增节点可配属性的时机 | **必须先保存画布**拿到 nodeId | 画布建形状后立即自动保存，立即可配 |
| 删除机制 | 前端 diff 出 `deleteNodes` → `WFNodeMainManager.deleteWfNode` 连带清理 | 后端按 `seenNodeKeys` 差集删除（**目前漏删 `wf_node_field_perm`**） |
| 设置项对画布的影响 | **有**（cell.style 加 icons 角标） | 无（仅存 `ext_json`） |
| 详情数据获取 | 一次性 `getWfInfo` 拉全量 `nodeDatas`，按 nodeId 取 | `listNodes` + 按节点 `getNodeOperators` / `getFieldPerm` |
| 面板显示哪些行 | 受 `workflowDatas` 开关（超时/日志/二次认证）与节点属性动态控制 | 固定 13 列（schema 静态） |
| 未保存节点的处理 | 明确提示"请先保存流程图" | 新增即自动保存，无此提示 |

### 7.8 可借鉴到本系统的三点

1. **未落库节点的显式提示**：本系统新增节点会自动保存，暂无需要；若将来支持"纯表单新增"，应对无 nodeKey 的行给出等价提示。
2. **设置项反向标注画布**：参考 E9 的 `checkIsChangCellIcon`，可让「节点前/后附加操作」「超时设置」等已配置项在画布节点上以角标呈现，一眼看出哪些节点配过什么。
3. **面板行项动态化**：E9 按 `workflowDatas` 开关与节点类型决定显示哪些行；本系统可让「超时设置」列仅在流程开启超时时显示、「合并类型」仅在合并节点显示，减少空列。

## 8. 结论与后续建议

1. **字段覆盖度**：「节点信息」区域共 **23 个字段/配置组**（13 列表格列 + 基本属性 9 项（含 2 项与表格列重复）+ 字段权限矩阵 + 节点级表单布局），本文档已全覆盖。
2. **生效范围**：真正参与运行时的只有 `wf_process_node` 表字段（名称/类型/审批方式/合并/开关）与 `wf_node_operator`、`wf_node_field_perm`；`ext_json.settings` 的 10 个设置项目前**只存不生效**。
3. **若要让设置项生效**，需在流转运行时按 `ext_json.settings` 派发，建议优先级：操作菜单 → 签字意见必填 → 超时/提醒 → 节点前后附加操作 → 表单日志范围 → 异常处理 → 子流程 → 指定流转 → 标题模板。
4. **E9 差异补齐建议**：
   - 指定流转增加「模式位」（`SelectNextFlowMode`：1 指定节点+操作者 / 2 只指定节点）；
   - 表单日志查看范围改为「可见节点 ID 集合」，与 E9 `viewnodeids` 对齐；
   - 操作者补齐 `groupNo / levelMin / levelMax / signOrder / conditionJson`（表结构已存在，仅前端未暴露）；
   - 视需要补「二次认证设置」与「节点字段校验」。
5. **本系统画布关联**（见 §6）：`nodeKey` = BPMN 元素 id，是节点信息与画布的唯一纽带；画布管结构、节点信息管语义；改名必须回写画布，否则保存画布时被回滚。
6. **E9 画布关联**（见 §7）：纽带是 `cell.nodeId`（mxCell 自定义属性），`graph.workflowDetailDatas.nodeDatas[nodeId]` 供面板取数；E9 是「画布单向权威」（节点表即图形表，含坐标 `drawxpos/drawypos`），故改名无回滚风险、删除靠画布 diff；且设置项会反向在画布节点上加角标。可借鉴：设置项角标化、面板行项按流程开关/节点类型动态化。
7. **待修缺陷**：`saveBpmn` 删除节点时未清理 `wf_node_field_perm`（§6.5-6），会残留孤儿权限行，建议补删。
7. **验证提示**：修改前端组件后需重启 8000 端口的 dev server（Umi MFSU 缓存）；Playwright 无法自动登录验证，请在已登录浏览器硬刷新确认。

## 9. v1.1 变更记录（设置项运行期生效 + 新增能力）

> 日期：2026-09-12。本节记录本轮把「只存不生效」推进为「运行期生效」的实现与新增字段。

### 9.1 运行期消费现状（`ext_json.settings`）

| 设置项 | 运行期位置 | 行为 |
| --- | --- | --- |
| `operateMenu` | `WfTaskServiceImpl#doApprove/reject/forward` | 校验操作是否开放（未配置=不限制） |
| `signOpinion` | `WfTaskServiceImpl#resolveOpinion` | 意见必填校验 + 缺省套用默认模板 |
| `timeout` | `WfInstanceServiceImpl#resolveDueTime` + `WfTimeoutJob` | 写 `due_time`；到期扫描，`autoApprove` 自动通过 / `remind` 提醒 |
| `preOperate` / `postOperate` | `NodeActionExecutor#execute` | 节点前/后执行附加操作（http / sql / field） |
| `formLogScope` | `WfInstanceServiceImpl#logs` | 按 `nodeKeys` 过滤可见节点日志 |
| `exceptionHandle` | `NodeActionExecutor` | 附加操作/子流程失败时 continue（跳过）/ stop（中断） |
| `subflow` | `NodeActionExecutor#triggerSubflow` | 提交后 / 归档后发起子实例（回填 `parentId`） |
| `appointFlow` | `WfTaskServiceImpl#doApprove` | 处理人手动指定下一节点（模式 1 可指定操作者） |
| `titleDisplay` | `WfInstanceServiceImpl#resolveTitle` | 首节点标题模板（占位符解析） |
| `secondAuth`（新增） | `WfTaskServiceImpl#validateBeforeApprove` | 同意前校验密码（用户中心 `verifyPassword`） |
| `fieldCheck`（新增） | `WfTaskServiceImpl#validateBeforeApprove` | 按规则校验表单快照 |
| `formContent` | 前端 + `form_layout` | 节点级 Excel 布局（既有） |

### 9.2 新增字段（`ext_json.settings`）

- `secondAuth: { required: boolean }` —— 二次认证（对齐 E9 `hasSecondAuth`）。同意时需携带明文密码 `ApproveDTO.password`，后端经 `IUserClient#verifyPassword` 校验。
- `fieldCheck: { script: string }` —— 节点字段校验（对齐 E9 `hasNodePro`）。`script` 每行一条规则：`字段:required` / `字段:regex=正则` / `字段:min=数字` / `字段:max=数字`。

### 9.3 指定流转（appointFlow）运行期

- `ApproveDTO` 新增 `nextNodeKey` / `nextAssignee`。
- 当前节点 `appointFlowMode != 0` 且为人工办理时：校验目标节点存在且非当前节点 → `IProcessService#moveActivity`（Flowable `changeActivityState`）→ `advance(..., overrideNodeKey, overrideAssignee)` 同步待办。
- 模式 1：用户指定操作者覆盖目标节点；模式 2：忽略用户操作者，按目标节点设置解析。
- 系统自动通过（超时）时跳过本项，走默认流向。

### 9.4 附加操作执行器

- `WfActionExecutor` 按 `script` 前缀分派：`http(s)://`（JDK HttpClient GET）、`sql:`/`dml:`（JdbcTemplate）、`field:`/`set:`（写最新表单快照）；其它前缀仅记录日志。
- 安全开关 `blade.workflow.action`：`http-enabled` / `sql-enabled`（默认 false）、`http-timeout-ms`、`url-whitelist`。未开启时按「未配置」跳过。
- 失败由「流程异常处理」`mode` 保护，不阻塞主干。

### 9.5 前端

- `SETTING_DEFS` 新增「二次认证设置」「节点字段校验」两行（弹出配置）。
- 画布节点角标：`BpmnDesigner` 用 overlays 在节点右上角标注已配置设置项数量（`configuredBadges`，对齐 E9 `checkIsChangCellIcon`）。
- 节点设置行项动态化：`NodeDetail` 的「超时设置」仅在审批(1)/提交(2) 节点显示。
- 保存画布后 `setSelectedNodeKey(undefined)`（见 §6.5-7）。

### 9.6 待办

- 指定流转的**处理端 UI**（手动选择下一节点/操作者）尚未接入前端待办页（当前仅有 `services/workflow` 接口封装），可后续在待办详情弹窗补充。
