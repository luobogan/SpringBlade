## 4. 七份文档的共同结论（共识基线）

1. **单一事实源分域**：流程执行语义归 Flowable（`wf:` 扩展随 BPMN 版本化），业务态/草稿/激活版本/表单/自由流程开关归 SB 业务侧。依据《去wf_表-定义主记录翻源设计.md:42》D2 职责切分。
2. **当前是"中深度、不均衡"使用**：UserTask 主链 + 会签 + 条件 UEL + 事件反写 + ACT 读源做得深；消息/信号、异步定时、自动节点、补偿、生态集成大面积空白。
3. **全量启用的前置是"桥 + 动作执行"**：引擎→SB 正向桥（E7：ACTIVITY_COMPLETED 监听 + advance 建待办 + 归档判定改 ended 信号）与自动节点动作执行（E1：ServiceTask delegateExpression + 带 gate 的 action 执行）均已落地首版、默认全关；两者配套灰度，缺任一都不启用自动节点。
4. **三条 invariant 不可破**：单一事实源不倒退、在途实例钉版本不放宽、测试态隔离不依赖调用方自觉。
5. **推进顺序**：防呆 → 桥与闸门 → 自动化事件 → 可观测 → 定时协作 → 深度扩展（脚本/DMN 最后）。
6. **AsyncExecutor 硬约束**：三项兜底（最终一致、常驻对账、deadletter 告警）已齐备并在 dev 随 S5 开启激活（§9.17）；超时仍用 `WfTimeoutJob` 扫表兼容路径。S3 timer 轮询与 AsyncExecutor 互斥（启动自检 `log.error`），二选一。
