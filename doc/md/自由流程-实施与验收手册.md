## 1. 架构决策（与初版方案的差异）

初版分析 §5.2 设想「实例级动态节点 + 免模型引擎」。第二轮复查（分析文档 §10.1）发现该路线会被 `def_id + node_key` 全链路索引打断，且 `instance-read-source=act` 会让无引擎实例隐形。**实施采用「静态节点池绑定 + 实例级步骤编排 + 影子节点装饰」**：

| 层 | 实现 |
|---|---|
| 定义期 | BPMN 内预置 `Free_1..Free_N` 真实 UserTask（每个带一条到 EndEvent 的默认出口） |
| 实例期 | `wf_free_node` / `wf_free_link` 存本次单据的步骤（名称/办理人/会签/角色标记/顺序） |
| 运行期 | `wf_task.node_key` 恒为池内静态 key，`WfFreeNodeResolver` 把静态节点装饰成本实例该步骤的 `WfProcessNode` |
| 推进 | 中间步 `moveActivity` 池内迁移；末步 `completeTask` 走 EndEvent，由既有 `advanceInternal` 空任务分支归档 |

**收益**：公文四钩子、字段权限、操作菜单、超时、进度图、快照等以 `def_id+node_key` 为索引的链路**无需重写**，规避 §10.1 的连锁静默失效；仍持有 Flowable 运行态，act 读源不隐形。
**代价**：单实例自由步骤上限 = 节点池容量 N（默认 5，可配到 20），超出需在设计器调大并重新发布。

## 3. 配置步骤（流程管理员）

1. 进入「流程设计 → 基础设置」，打开「是否为自由流程」。
   - 文案已修正为实际语义（自选下一步/办理人 + 流转设定编排），移除了旧「启用后不允许关闭」的误导提示。
   - 「自由流程类型」本期仅**简易模式**；「通用节点数量」默认 5，范围 1–20。
2. 点击「按新数量重建默认画布」生成 `Free_1..Free_N`（**会重置画布上的手工编辑**）。
3. 保存后**必须点「发布」**（`POST /definition/{id}/deploy`）：`saveBpmn` 只写草稿 `bpmn_xml`，运行期 `loadNode` / `WfRejectManager` / `moveActivity` 读的是 `proc_def_id` 指向的那次部署。
   - 若同时调整会签方式，执行「重新部署多实例」(`/definition/admin/redeploy-mi`)。
4. 验收：`SELECT proc_def_id, deployment_id FROM wf_process_definition WHERE id=?` 非空。

## 4. 使用步骤（办理人）

| 功能 | 入口 | 说明 |
|---|---|---|
| 流转设定 | 办理页「流转设定」按钮 | 按本次单据编排步骤：增删行、排序、命名、选多人、会签方式、定稿取号/套红标记。整包保存带 `version` 乐观锁与 `saveToken` 幂等键 |
| 下一步设置 | 办理页「下一步设置」按钮 | 选节点（服务端白名单）、选多人、选会签方式后直接提交 |
| 模板 | 流转设定内「另存为模板 / 从本地模板导入」 | 保存在浏览器 `localStorage`（键 `wf_free_flow_templates`），不跨设备同步 |
| 退回 | 既有「退回」按钮 | 候选改由 `wf_free_link` 正向链提供；退回后自动重置目标步骤及之后的「已流转」状态 |
| 归档 | 末步提交 | `completeTask` 走 EndEvent，沿用既有归档日志/终态双写/子流程回调 |

**权限口径（WF-N9）**：`GET /free-flow/next-nodes` 只接受 `taskId`，候选由服务端按池容量生成并排除当前节点；`steps/save` 做实例级鉴权（`requireStarterOrAdmin`）；`doApprove` 对目标节点与办理人做服务端二次校验。不以出口条件求值作为门禁。

## 8. 已知限制（明确裁剪，非缺陷）

1. **节点池上限**：单实例自由步骤数 ≤ `free_node_pool_size`（默认 5，最大 20）。调大需重建默认画布并重新发布。
2. **模板持久化**：仅浏览器 `localStorage`，不跨设备/不入库。若需团队共享，需新增 `wf_free_flow_template` 表 + 共享范围（参考 E9 `freeflow_template_share` Cmd 族）。
3. **进度图/流转意见显示**：四色上色正常；节点名与「接收人」在 `logs`/`progress` 仍读定义态，未用 `wf_free_node` 补映射（按分析文档 §10.1 属"可选增强"）。
4. **会签 5 值**：运行期只实现 0/1/2；`CC_NO_SUBMIT(3)/CC_SUBMIT(4)` 与 `nodetype=4` 传阅需提交门禁未实现（避免按注释误判已支持）。「依次逐个」已具备。
5. **超时字段级差距**：缺 `advanceRemind` / 循环提醒 / `overtimeToNextOperator` / 指定日期形态；规则仍是定义期静态。**必须给每个 `Free_k` 配超时规则**，否则 `WfTimeoutJob` 会因无规则把任务标记 `timeout_handled=1` 后永久不再触发（无 ERROR 日志）。
6. **公文 odoc 六权限**：`odoc_freeflow_manager`（改签/代录意见/收回/改办理人/归档/调整日志）未纳入本期，springBlade odoc 目录无对应表/端点。
7. **代理 / 自动批准特殊分支**：E9 自由流程下的 `isFlowToNext` 加签、代理还原等分支未实现（springBlade 代理设置本身亦缺）。
8. **移动端**：无移动端办理页与选人 UI。
9. **并列待办超时**：`appendExtraAssignees` 让 N 人共享同一 `engineTaskId`，超时动作可能只作用于首人或重复标记，需按实际业务回归。
