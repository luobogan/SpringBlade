# 建模字段权限通用化配置方案（授权对象优先）

> 日期：2026-11-21  
> 状态：方案分析，不含代码改动  
> 目标：解决“字段权限按单张表逐条配置，维护量过大”的问题。

---

## 1. 背景与问题

当前字段权限入口是：

```text
/formmode/formmanage → 某张表单 → 权限 → 字段权限
```

配置方式：

```text
表单/模块维度 → 新增一条字段权限 → 选字段 → 选授权对象 → 选权限值
```

一条记录表达：

```text
某个字段 + 某个主体 + 某个权限值
```

例如：

```text
fieldid=4607, objtype=1, objid=4000000008, rightvalue=2
```

表示字段 `4607` 对角色 `4000000008` 可编辑。

### 当前痛点

1. 字段多、角色多时配置量呈乘积增长。
2. UI 一条一条添加，维护成本极高。
3. 同一套角色权限要在多个表单中重复配置。
4. 缺少“按主体统一维护字段权限”的入口。

---

## 2. 数据权限那边当前是怎么做的

数据权限字段配置流程是：

```text
租户 → 菜单/资源 → 数据权限规则 → 新增/编辑规则 → 选择业务表单 → 勾选可见字段
```

关键文件：

- `ant-design-pro/src/pages/Authority/Datascope/Datascope.tsx`
  - 菜单/规则配置：`589-635`
  - 规则弹窗：`638-683`
  - 新增规则：`685-808`
  - 编辑规则：`810-927`
  - 可见字段表单项：`784-798`、`904-917`
- `ant-design-pro/src/pages/Authority/Datascope/components/VisibleFieldSelector.tsx`
  - 字段选择区：`371-405`
  - 选业务表单加载字段：`1012-1033`
  - 加载字段：`421-477`
  - 字段勾选：`876-886`
  - 全选/清空/反选：`900-923`

数据权限字段配置主要落在：

```text
blade_scope_data.scope_field
blade_scope_field
```

角色与数据权限规则的绑定落在：

```text
blade_role_scope(role_id, scope_id, scope_category)
```

### 关键结论

数据权限当前**不是**：

```text
先选授权对象 → 勾字段
```

而是：

```text
先选菜单/规则 → 选业务表单 → 勾字段
```

角色授权是在角色管理页单独完成的：

```text
角色 → 权限配置 → 勾选数据权限规则
```

因此，用户提出的“先选授权对象类型/对象，再弹窗勾选字段”是一个新的建模字段权限配置视图，可以参考数据权限字段选择组件，但不能直接照搬流程。

## 3. 建模字段权限当前机制

核心表：

```text
modefieldauthorize
```

关键字段：

```text
id
modeid
fieldid
objtype
objid
includesub
rightvalue
tenant_id
```

权限值：

```text
0 = 隐藏
1 = 可见
2 = 可编辑
```

运行期计算：

```text
FormRightServiceImpl.listFieldPerm(modeId)
```

文件：

- `SpringBlade/blade-service/blade-formmode/src/main/java/org/springblade/formmode/service/impl/FormRightServiceImpl.java:469-540`

语义：

1. 按 `modeId + tenant` 查字段授权。
2. 当前用户展开角色/部门/岗位/分部等主体。
3. 多条命中同一字段时取最宽松：

```text
rightvalue = Math.max(...)
```

即：

```text
可编辑(2) > 可见(1) > 隐藏(0)
```

4. 模块有授权但当前用户未命中任何字段时：
   - 兼容档：返回空，调用方按默认渲染
   - 严格档：返回全部字段且 `visible=false`

当前保存接口：

```text
POST /right/all/{modeId}
```

字段权限保存是：

```text
按 modeId + tenant 删除全部字段授权 → 插入本次传来的全部字段授权
```

问题：

- 保存维度是 `modeId`
- 不是 `(objtype, objid)`
- 不支持跨表单只改某一个主体的字段权限

---

## 4. 用户需求重新定义

用户要的不是“某张表的字段权限矩阵”，而是：

```text
选择授权对象类型
  ↓
选择具体授权对象
  ↓
弹出/打开字段勾选配置
  ↓
可跨多张表/多个表单勾选字段并设置权限
  ↓
一次保存该主体的字段权限
```

也就是从：

```text
表单视角
```

变为：

```text
主体视角
```

例如：

```text
选择：角色 = 部门领导
  ↓
选择表单：集团公司发文、集团部门收文、差旅报销
  ↓
分别勾选字段并设置权限
  ↓
一次保存
```

---

## 5. 可行性结论

可以做，且建议做。

核心原则：

> 对象优先界面只是“编辑视图”，不能另起一套运行期权限表。

运行期仍然必须走：

```text
modefieldauthorize → listFieldPerm → 当前用户动态聚合
```

否则会形成两套权限体系，造成口径冲突。

### 与模块权限的边界

| 配置类型 | 推荐入口 | 存储 |
|---|---|---|
| 模块操作权限 | 表单权限抽屉 | `moderightinfo` |
| 数据范围 | 表单权限抽屉 | `modedatasharerule` |
| 单表字段权限细节 | 表单权限抽屉 | `modefieldauthorize` |
| 按主体跨表维护字段权限 | 新增对象优先页面/抽屉 | 仍写 `modefieldauthorize` |
| 菜单显示名 | 角色权限 / 建模权限快捷入口 | `blade_role_menu_name` |

对象优先界面只处理字段权限，不改模块权限、数据范围、菜单授权。

## 6. 为什么不能直接复用 `saveAll`

当前：

```text
saveAll(modeId, batch)
```

是模块级全量替换，会同时替换：

```text
moderightinfo
modefieldauthorize
modedatasharerule
```

问题：

1. 保存主体不匹配  
   对象优先保存的是 `objtype + objid` 跨多个 `modeId` 的字段权限。

2. 会误删其它主体的字段权限  
   当前字段权限删除维度是 `modeId + tenant`，对象优先需要 `modeId + objtype + objid + tenant`。

3. 会误碰模块权限和数据范围  
   对象优先字段配置只应该动 `modefieldauthorize`。

4. 版本维度不匹配  
   当前版本是 `modeId` 级，跨主体一次编辑需要主体级版本或受影响模块版本校验。

## 7. 推荐设计

### 7.1 新增入口

建议新增：

```text
权限管理 / 建模字段权限（按主体）
```

或在字段权限 Tab 增加模式切换：

```text
[按表单配置] [按主体配置]
```

更推荐独立页面/抽屉，因为对象优先配置天然跨表单。

### 7.2 配置流程

#### Step 1：选择授权对象类型

支持：

```text
1 角色
2 部门
3 岗位
4 人员
5 分部
7 矩阵
```

第一版建议先支持：

```text
角色
```

因为字段权限维护绝大多数是角色维度。

#### Step 2：选择具体对象

复用现有 `ObjPicker`：

- `FormRightDrawer.tsx:106-223`

#### Step 3：选择要配置的表单

支持：

```text
搜索表单
多选表单
按表单名筛选
按已配置/未配置筛选
```

#### Step 4：字段勾选/权限设置

参考 `VisibleFieldSelector`，但做成建模语义：

```text
字段中文名
字段名
字段类型
权限值：隐藏 / 只读 / 可编辑
```

支持：

```text
全选 / 清空 / 反选
按表单全选
按字段搜索
批量设置只读
批量设置可编辑
批量隐藏
```

#### Step 5：一次保存

只保存当前主体的字段权限，按主体差异更新。

## 8. 后端接口设计

### 8.1 查询主体字段权限

```http
GET /api/blade-formmode/right/field/subject?objtype=1&objid=4000000008
```

返回：

```json
{
  "success": true,
  "data": [
    {
      "modeId": "2109677294030196738",
      "formId": "2109677294030196738",
      "formName": "集团公司发文",
      "fields": [
        {
          "fieldId": 4607,
          "fieldName": "gwbt",
          "fieldLabel": "公文标题",
          "rightvalue": 2
        }
      ]
    }
  ]
}
```

### 8.2 按主体批量保存字段权限

```http
PUT /api/blade-formmode/right/field/subject/batch
```

请求体：

```json
{
  "objtype": 1,
  "objid": "4000000008",
  "tenantId": "000000",
  "expectedVersion": 12,
  "modes": [
    {
      "modeId": "2109677294030196738",
      "fields": [
        { "fieldId": 4607, "rightvalue": 2 },
        { "fieldId": 4608, "rightvalue": 1 },
        { "fieldId": 4609, "rightvalue": 0 }
      ]
    }
  ]
}
```

注意：

- `objid`、`modeId` 必须支持字符串，避免雪花 ID 精度丢失。
- `expectedVersion` 可以是主体级版本，也可以是受影响模块版本校验结果。

### 8.3 保存语义

服务端按主体差异保存：

对于本次涉及的每个 `modeId`：

1. 查出旧记录：

```text
tenant + objtype + objid + modeId
```

2. 对提交的字段：

```text
已有 → 更新 rightvalue
没有 → 插入
```

3. 对旧记录中“本次未提交”的字段：

```text
删除
```

4. 其它主体、其它模块：

```text
不动
```

5. 不碰：

```text
moderightinfo
modedatasharerule
菜单授权
```

6. 保存后清理缓存：

```text
formmode:field-perm
formmode:right-check
```

7. 写审计日志。

## 9. 数据结构建议

### 9.1 运行期表不变

继续写：

```text
modefieldauthorize
```

不要新增另一张字段权限运行期表。

### 9.2 建议加唯一索引

当前 `modefieldauthorize` 没有唯一索引。

建议先去重后加：

```sql
UNIQUE KEY uk_field_auth_subject
(tenant_id, objtype, objid, modeid, fieldid)
```

### 9.3 建议加主体级版本表（第二阶段）

如需跨表单一次保存并做乐观锁，建议加：

```text
formmode_field_auth_subject_version
```

字段：

```text
tenant_id
objtype
objid
version
updated_by
updated_at
```

主键：

```text
tenant_id + objtype + objid
```

第一阶段也可以不加，改为保存前逐个校验受影响 `modeId` 的现有版本。

## 12. 风险与决策点

### 12.1 未配置语义

当前建模字段权限语义是：

```text
模块有配置但当前用户未命中 → 字段隐藏（严格档）
```

对象优先配置中，如果用户只配置了部分字段，其它字段是否隐藏必须讲清楚。

建议：

```text
界面默认展示全部字段
用户显式设置每个字段的隐藏/只读/可编辑
“未设置”单元格不落库
保存前提示：未设置字段将沿用当前 fail-open/fail-closed 规则
```

### 12.2 多主体冲突

同一字段命中多个主体时，当前取最宽松：

```text
2 > 1 > 0
```

对象优先保存时要避免同一主体重复行。

### 12.3 数据量

76 字段 × 6 角色 = 456 条，可以接受。  
132 字段 × 7 角色 = 924 条，也可以接受。

但必须：

```text
批量保存
批量删除
不要逐条 API
```

### 12.4 权限边界

第一版建议只做角色维度。

原因：

- 角色是实际维护中最常用主体
- 部门/岗位/人员/分部/矩阵配置复杂度高
- 多主体类型同时做矩阵会导致界面复杂化

## 13. 分阶段实施建议

### 阶段一：对象优先配置基础版

范围：

```text
角色维度
跨表单选择
字段勾选
权限值设置
按主体差异保存
```

改动：

1. 新增前端页面/抽屉
2. 新增 `GET /right/field/subject`
3. 新增 `PUT /right/field/subject/batch`
4. 建议加唯一索引
5. 保持运行期 `listFieldPerm` 不变

验收标准：

```text
选择一个角色后，能看到该角色跨表单的字段权限
勾选多个表单和字段后，一次保存成功
只影响该角色，不影响其它角色
不改动模块权限和数据范围
运行期用户看到的字段权限立即生效
```

### 阶段二：页面内 Excel 式批量工具

在对象优先配置中增加：

```text
按表单全选
批量设置权限
复制角色配置
字段搜索
折叠展开
导入预览
```

### 阶段三：Excel 文件导入导出

增加：

```text
导出模板
导入校验
差异预览
增量合并/按主体覆盖
```

### 阶段四：默认策略 + 例外字段

长期终态：

```text
默认权限 + 例外字段
```

例如：

```text
部门领导：默认只读
例外：公文标题=可编辑，密级=隐藏
```

这样维护量从：

```text
字段数 × 主体数
```

降到：

```text
例外字段数 × 主体数
```

## 14. 最终结论

用户的思路是对的：字段权限不应该只能按单张表逐条配置，应该支持“先选授权对象，再跨表单勾选字段”的对象优先配置。

但要注意：

1. 运行期权限引擎不变，仍然用 `modefieldauthorize + listFieldPerm`。
2. 对象优先界面只是新的编辑视图。
3. 需要新增按主体差异保存接口，不能复用 `saveAll`。
4. 第一版建议只做角色维度，降低复杂度。
5. Excel 文件导入导出作为第二阶段，页面内 Excel 式批量操作优先。
6. 长期可以看“默认策略 + 例外字段”，从根本上降低配置量。
