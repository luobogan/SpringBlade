# 企业统一消息中心（Enterprise Unified Message Center）设计文档

> **模块代号**：`message`
> **参考需求**：微信公众号《SpringBoot+WebSocket×场景×渠道：企业统一消息中心编排实战》（https://mp.weixin.qq.com/s/4Mh4DnJ_Fww45f2Y4gOiDQ）
> **后端基线**：SpringBlade 开源微服务版（Cloud、Java 21、MyBatis-Plus、Nacos）—— 遵循 `SpringBlade/CLAUDE.md`
> **前端基线**：Ant Design Pro（Umi Max v4、antd v6、ProComponents v3）—— 遵循 `ant-design-pro/CLAUDE.md`
> **仓库既有可复用模块**：`blade-resource`（附件/对象存储）、`blade-workflow-api`（`IWorkflowClient` 流程契约）、`blade-desk`（`Notice` 通知公告，作差异化参照）

---

## 一、模块目标

在企业内部建立**统一、实时、可追溯**的人员间消息通道，替代各业务模块零散的"站内信/邮件/弹窗"，满足：

1. **人员之间发送消息**：支持一对一与群组会话，消息含文本、富文本（链接）、附件。
2. **上传附件**：消息可携带文件，附件统一交由 `blade-resource`（OSS/MinIO）托管，消息仅存引用。
3. **引用流程**：消息可关联业务对象（重点为工作流实例 `wf_instance` / 任务 `wf_task`），点击"去处理"跳转对应流程页。
4. **保障及时性**：消息**先落库**（可追溯、可补偿），再经 WebSocket **尽力推送红点与新消息**；推送失败由"重连拉取未读数"兜底，杜绝"角标不跳"。
5. **多租户隔离**：会话、消息、附件均按 `tenant_id` 字段隔离，与 SpringBlade 租户框架一致。

> 与参考文章的关系：文章面向"事件通知编排引擎"（sceneCode → 多渠道 → Instance/SendLog），本模块以"**人员会话消息**"为主体并吸收其精华范式——**落库 + WS 尽力推 + 补偿拉取**、`bizId/bizType` 防腐层、红点与聊天类型分离。附件与流程引用为文章未覆盖、本需求明确要求的能力。

## 三、前后端分层设计

### 3.1 后端分层（严格遵循 `CLAUDE.md` §2.1 / §6）

新增业务域**先建 API 模块再建 Service 模块**：

```
SpringBlade/
├── blade-service-api/
│   └── blade-message-api/                 # 仅契约，不含业务逻辑
│       └── org/springblade/message/
│           ├── entity/                     # Session / SessionMember / Message / MessageAttachment / MessageReadLog
│           ├── vo/                         # SessionVO / MessageVO / MessageAttachmentVO
│           ├── dto/                        # MessageSendDTO / MessagePageDTO / SessionCreateDTO
│           └── feign/                      # IMessageClient + IMessageClientFallback
└── blade-service/
    └── blade-message/                      # 业务实现
        └── org/springblade/message/
            ├── controller/                 # SessionController / MessageController / MessageWsController
            ├── service/  + service/impl/    # ISessionService / IMessageService ...
            ├── mapper/  (+ xml 同包)        # XxxMapper
            ├── wrapper/                     # MessageWrapper / SessionWrapper（Entity→VO）
            ├── feign/                       # IMessageClient 服务端实现（@RestController）
            ├── websocket/                   # WS 配置、HandshakeInterceptor、消息推送器
            └── event/                       # （可选）监听工作流事件自动发消息
```

**Entity 继承体系（§6.2）**：消息均为多租户业务数据 → 统一 `extends TenantEntity`，Service 用 `BaseService<T>` / `BaseServiceImpl<M,T>`。

**Feign 契约（§6.4）**：
- `IMessageClient` 定义在 `blade-message-api` 的 `feign/`，供其他服务（如 `blade-workflow` 审批完成后调 `send`）依赖。
- 路径常量 `API_PREFIX = "/message"`；方法 `API_PREFIX + "/send"`。
- 降级类 `IMessageClientFallback`（同包、`@Component`，返回安全缺省值）。
- 服务端实现位于 `blade-message/feign/`，`@RestController implements IMessageClient` 复用内部 Service。

**附件存储**：复用 `blade-resource` 服务（OSS/MinIO），**不自建文件存储**。前端直传或 Service 侧经其 Feign 上传，消息表仅存 `file_id`/`file_url`/`file_name`/`file_size`。

**流程引用**：复用既有 `blade-workflow-api` 的 `IWorkflowClient`（已存在 `startProcess`、`getDefinitionKeyAndTenant` 等）；引用对象以 `bizRefType`（如 `WF_INSTANCE`/`WF_TASK`）+ `bizRefId`（字符串，19 位雪花 ID 须用 `String` 防精度丢失，见 §6.3/§7.3）表达。

## 四、关键流程

### 4.1 发送文本/附件消息（主流程）

```
[前端 ChatPanel]
  1. 组装 MessageSendDTO{sessionId, content, contentType,
     attachments:[fileId...], quoteMessageId?, bizRefType?, bizRefId?}
  2. POST /blade-message/message/send
        │
[MessageController] → [MessageServiceImpl.send]
  3. 校验会话成员归属（Sender 必须在 session_member，且同租户）
  4. 落库 blade_message（status=SENT，tenant_id 自动注入）
  5. 若有 attachments → 落库 blade_message_attachment（关联 message_id）
  6. 若有 quote/bizRef → 写入引用字段
  7. 发布"新消息"事件到 Redis 频道 message:{tenantId}:{sessionId}
        │
[MessageWebSocketPublisher]（各实例订阅 Redis）
  8. 向在线成员推送 STOMP：/user/{userId}/queue/message（payload=MessageVO）
  9. 向在线成员推送 /user/{userId}/queue/unread（红点+1）
        │
[前端 messageSocket] 收到 → 刷新聊天窗 + SessionList 角标 + MessageBell 红点
```

### 4.2 已读回执

```
用户打开会话 → POST /blade-message/message/read {sessionId}
  → 批量写 blade_message_read_log（message_id, user_id, read_time）
  → 清零该会话未读；推送 /user/{userId}/queue/unread（红点归零）
```

### 4.3 重连/补偿（实时性兜底）

```
前端 WS 断开重连成功（或首屏加载）
  → GET /blade-message/message/unread-count → 校正全局红点
  → GET /blade-message/session/{id}/messages?lastId= → 增量补拉离线消息
```
> 文章范式落地：WS 推送失败仅 `warn`，**不影响落库**；用户打开铃铛仍可见历史，下次心跳拉未读。

### 4.4 创建会话

```
POST /blade-message/session/create {memberIds:[...], name?}
  → 两人会话幂等（已存在则复用）→ 群会话新建
  → 写 blade_message_session + blade_message_session_member
```

## 五、附件与流程引用机制

### 5.1 附件机制

- **存储（已定 D1）**：前端 `AttachmentUpload` **直传** `blade-resource`（OSS/MinIO），拿到 `fileId`/`url`；Service 侧经 Feign 上传本版**不实现**，仅保留直传单一路径。理由：降低消息服务压力、避免在 `blade-message` 重复持有 OSS 密钥。
- **关联**：`MessageSendDTO.attachments = [fileId]`；`MessageServiceImpl` 在落库 `blade_message` 后，按 `fileId` 批量写 `blade_message_attachment`。
- **展示**：`MessageItem` 渲染为卡片（文件名/大小/图标），点击新标签页打开 `file_url`（带鉴权 token）。
- **清理**：消息删除走逻辑删除（`is_deleted=1`）；OSS 文件由 `blade-resource` 侧生命周期/清理策略负责，消息中心不物理删文件。

### 5.2 流程引用机制（防腐层）

- **表达方式**：消息表 `biz_ref_type`（`WF_INSTANCE` / `WF_TASK` / 其他业务）+ `biz_ref_id`（字符串，19 位雪花 ID）。
- **选择**：`BizReferencePicker` 调 `blade-workflow`（`IWorkflowClient` 或前端经网关直连 `/blade-workflow/...`）列出当前用户相关实例/任务，回填 `bizRef*`。
- **跳转**：`MessageItem` 渲染"流程卡片"，点击 → 路由 `/workflow/...?id={bizRefId}`（与既有工作流前端页一致）。
- **自动联动（可选）**：`blade-workflow` 审批完成/转办时，经 `IMessageClient.send(...)` 自动给相关人发"流程消息"，复用同一张表，`bizRefType=WF_TASK`。
- **精度**：`bizRefId` 与 Snowflake 一致，Java 用 `String`、前端用 `string`，避免 JS 精度丢失（同 `IWorkflowClient.startProcess` 返回值处理）。

## 六、消息实时性方案

SpringBlade 开源版**无内置 WebSocket 模块**，故在本模块自建：

### 6.1 传输

- **协议**：STOMP over SockJS（兼容浏览器/代理）；端点 `blade-message` 内 `/ws/message`。
- **网关路由**：`blade-gateway` 增加 WS 路由 `Path=/blade-message/ws/**` → `Uri=lb:ws://blade-message`（Gateway 的 `WebsocketRoutingFilter` 自动识别 `ws://`）。
- **鉴权**：握手时前端带 `?token={JWT}`，`HandshakeInterceptor` 校验 JWT 并写入 `BladeUser` 上下文（同 `SecureUtil`）；非法拒绝握手。

### 6.2 推送

- **用户定向**：Spring WebSocket `SimpUserRegistry`，以 `userId` 为订阅主体 → `/user/{userId}/queue/message` 与 `/user/{userId}/queue/unread`。
- **集群**：多实例下用 `RedisMessageListenerContainer` 订阅 `message:{tenantId}:{sessionId}`；任一实例落库后发 Redis 事件，所有实例的 WS broker 推送给本实例在线成员。

### 6.3 红点与补偿

- **红点**：`/user/{userId}/queue/unread` 推送 `{sessionId, unreadCount, totalUnread}`；`MessageBell` 与 `SessionList` 消费刷新。
- **补偿**：WS 不可达 → 前端首屏/重连调 `GET /unread-count` 校正；聊天窗调 `GET /session/{id}/messages?lastId=` 增量补拉。
- **类型分离**：消息 WS 类型与现有 IM/通知类型分离（独立 destination），避免抢 handler（呼应文章）。

## 七、接口与数据结构定义

### 7.1 数据库表（多租户，`blade_` 前缀，雪花主键 `ASSIGN_ID`）

```sql
-- 会话
CREATE TABLE blade_message_session (
  id            BIGINT       PRIMARY KEY,
  tenant_id     VARCHAR(50)  NOT NULL,
  name          VARCHAR(100) COMMENT '群名称，两人会话可为空',
  type          TINYINT      NOT NULL COMMENT '1=两人 2=群',
  last_message  VARCHAR(500) COMMENT '最近一条摘要',
  last_time     DATETIME     COMMENT '最近消息时间',
  create_user   BIGINT, create_dept BIGINT, create_time DATETIME,
  update_user   BIGINT, update_time DATETIME,
  status        INT,  is_deleted INT DEFAULT 0,
  KEY idx_tenant (tenant_id)
) COMMENT '消息会话';

-- 会话成员
CREATE TABLE blade_message_session_member (
  id            BIGINT PRIMARY KEY,
  tenant_id     VARCHAR(50) NOT NULL,
  session_id    BIGINT       NOT NULL,
  user_id       BIGINT       NOT NULL COMMENT '参与人（blade_user.id）',
  unread_count  INT DEFAULT 0,
  pinned        TINYINT DEFAULT 0 COMMENT '置顶',
  mute          TINYINT DEFAULT 0 COMMENT '免打扰',
  create_user   BIGINT, create_time DATETIME,
  update_user   BIGINT, update_time DATETIME,
  status        INT,  is_deleted INT DEFAULT 0,
  UNIQUE KEY uk_session_user (session_id, user_id),
  KEY idx_user (user_id)
) COMMENT '会话成员';

-- 消息
CREATE TABLE blade_message (
  id            BIGINT PRIMARY KEY,
  tenant_id     VARCHAR(50) NOT NULL,
  session_id    BIGINT       NOT NULL,
  sender_id     BIGINT       NOT NULL COMMENT '发送人',
  content_type  TINYINT      NOT NULL COMMENT '1=文本 2=富文本 3=附件 4=流程引用',
  content       TEXT         COMMENT '文本/摘要',
  quote_msg_id  BIGINT       COMMENT '引用消息',
  biz_ref_type  VARCHAR(30)  COMMENT 'WF_INSTANCE/WF_TASK/...',
  biz_ref_id    VARCHAR(32)  COMMENT '业务对象ID（字符串防精度丢失）',
  status        TINYINT      NOT NULL DEFAULT 1 COMMENT '1=SENT',
  create_user   BIGINT, create_time DATETIME,
  update_user   BIGINT, update_time DATETIME,
  status_flag   INT, is_deleted INT DEFAULT 0,
  KEY idx_session (session_id, id)
) COMMENT '消息主体';

-- 附件
CREATE TABLE blade_message_attachment (
  id            BIGINT PRIMARY KEY,
  tenant_id     VARCHAR(50) NOT NULL,
  message_id    BIGINT       NOT NULL,
  file_id       VARCHAR(64)  COMMENT 'blade-resource 文件ID',
  file_name     VARCHAR(255),
  file_url      VARCHAR(500),
  file_size     BIGINT,
  file_type     VARCHAR(50),
  create_user   BIGINT, create_time DATETIME,
  is_deleted    INT DEFAULT 0,
  KEY idx_message (message_id)
) COMMENT '消息附件';

-- 已读回执
CREATE TABLE blade_message_read_log (
  id            BIGINT PRIMARY KEY,
  tenant_id     VARCHAR(50) NOT NULL,
  message_id    BIGINT       NOT NULL,
  user_id       BIGINT       NOT NULL,
  read_time     DATETIME,
  create_time   DATETIME,
  is_deleted    INT DEFAULT 0,
  UNIQUE KEY uk_msg_user (message_id, user_id)
) COMMENT '消息已读记录';
```

> SQL 脚本同步放 `doc/sql/`（全量 + 升级），遵循 §7 多库规范（MySQL/PG/Oracle/达梦等）。

## 九、开发与集成注意事项

1. **多租户隔离**：消息表均 `TenantEntity`；WS 用户主题按 `userId` 推送，但 `userId` 来自 JWT 中的租户上下文，天然单租户；Redis 频道带 `tenantId` 前缀防串租户。
2. **附件不重复建设**：一律走 `blade-resource`，消息中心只存引用，避免 OSS 账号/密钥重复配置。
3. **流程引用精度**：`bizRefId` 为字符串（19 位雪花），前后端均 `string`，禁用 `number`。
4. **实时性兜底**：WS 仅"尽力推"，落库为真相；红点以 `unread-count` 接口为准，重连必校正。
5. **网关与鉴权**：WS 路由 `lb:ws://`；握手 `?token=` 校验 JWT；非 WS 的 REST 走现有 `AuthFilter`，无需在 `skip-url` 放行（均需登录）。
6. **开源合规**：不引入商业版能力（Flowable/PowerJob/`@TenantDS` 等）；定时清理类需求用 Spring Boot 原生 `@Scheduled`，不依赖商业调度。
7. **Nacos 配置**：`blade-message` 的 `server.port`、数据源在 `application-dev.yml` 本地覆盖；公共参数（Redis、WS）在 Nacos `blade.yaml`。
8. **与 blade-desk 的差异**：`Notice` 是"公告广播"（非会话、无附件/已读逐人），本模块是"人员会话"（双向、附件、流程引用、实时），二者并存不冲突。
9. **测试与验证**：编译由 AI 执行 `mvn clean compile -DskipTests`；运行/接口联调交由人工（CLAUDE.md §4.2 禁止 AI 自启服务/自测）。
10. **FE 联调**：`npm run dev`（无 mock）连真实网关；`pages/Message/_mock.ts` 仅本地自测用，合入前按需保留。
