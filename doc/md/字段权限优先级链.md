# 字段权限源与优先级链（开发规范）

> 版本：v1.0 ｜ 日期：2026-09-10
> 归属：《审批流程方案-现状分析与技术选型》§3.5 / 《审批流程-开发任务说明》B4

## 1. 背景

系统里存在**三套字段权限源**，此前未界定叠加顺序，审批态渲染会出现「同一字段不同来源结论打架」。本文明确唯一优先级链，渲染端（PC `ExcelPreview` / 移动端 `MobileSheetForm` / 服务端校验）必须统一遵守。

| 权限源 | 位置 | 粒度 | 取值语义 | 现状 |
|---|---|---|---|---|
| `wf_node_field_perm` | blade-workflow（`WfPermController`） | **节点级**（def + nodeKey + scope + field） | `0隐藏 1只读 2可编辑 3必填` | 已实现 |
| `modefieldauthorize` | formmode（`FormRightController`） | 角色/部门/岗位/人员级（模块 + 字段） | `1可见 2可编辑`（`rightvalue`） | 已实现（`checkRight` 已改为按真实用户鉴权） |
| `fieldAttr` | formmode（`workflow_billfield` 字段定义） | 字段默认 | `1只读 2可编辑 3必填`（**建议补 `0=隐藏`**） | 设计期默认 |
| Excel 单元格样式 | 布局 JSON（`form_layout.layout_json`） | 单元格 | 字体/底色等展示属性 | 设计期 |

## 2. 优先级链（唯一权威）

```
wf_node_field_perm（节点级）
  > modefieldauthorize（角色/部门/岗位/人员级）
  > fieldAttr（字段定义默认）
  > Excel 单元格样式
  > 默认（可编辑）
```

**取「首个命中且更具体」的来源，不再向下叠加语义冲突**；仅当上游来源**未定义**该字段时，才回退到下一级。

## 3. 逐条规则

1. **节点级优先**：进入某审批节点后，若 `wf_node_field_perm` 对该字段（含 scope）有记录，直接采用其 `perm`，**不再**参考 `modefieldauthorize` / `fieldAttr`。
2. **scope 回退**（明细表）：`dt{idx}_r{row}`（精确行级） → `dt{idx}`（明细表级） → `main`（主表级） → 无记录则用 `fieldAttr`。
3. **模块级次之**：节点级无该字段记录时，取 `modefieldauthorize` 中当前用户（角色/部门/岗位/人员，`objid=0` 表示全部）命中的 `rightvalue`：
   - `2可编辑` → 可编辑（不强制必填）；
   - `1可见` → 只读。
4. **字段默认再次之**：以上均无 → 用 `fieldAttr`（`1只读 / 2可编辑 / 3必填`）。
5. **样式最后**：以上均无明确结论时，沿用 Excel 单元格自身样式；底色等**仅作展示**，不改变可编辑性判断次序（`fieldAttr` 底色优先级 > Excel bg）。
6. **默认**：都取不到 → `2可编辑`。

## 4. 语义映射（统一口径）

| 统一语义 | `wf_node_field_perm.perm` | `modefieldauthorize.rightvalue` | `fieldAttr` |
|---|---|---|---|
| 隐藏 | `0` | —（建议扩展） | `0`（D3 建议补） |
| 只读 | `1` | `1` | `1` |
| 可编辑 | `2` | `2` | `2` |
| 必填 | `3` | —（必填由节点级/字段默认给出） | `3` |
