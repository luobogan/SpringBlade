# 定义期回填与双轨对账方案（T-5 / P1）

> 来源：开发计划 P1（定义期下沉 + 回填迁移 + 双轨对账）。配套：`wf_BPMN扩展schema定稿.md`、`flow_def_bridge.sql`（T-2）。
> 目标：把现有 `wf_*` 定义期数据（节点/出口/操作者/字段权限/明细权限/超时/自定义动作/自定义操作）**转换并写回** BPMN `extensionElements`（`wf:` 命名空间），使引擎成为定义期唯一事实源；迁移期间保留 `wf_*` 只读，做双轨对账（只读告警）。

## 1. 回填范围（仅定义期 16 张表，不碰运行期 3 张）

| 来源表 | 目标 `wf:` 元素 | 备注 |
|---|---|---|
| wf_process_node | `userTask` 上的 `wf:node` 属性 | nodeType/signOrder/mergeType/allowReject... |
| wf_node_operator | `wf:node` 下 `wf:operator` | 多条 |
| wf_node_link | `sequenceFlow` 上的 `wf:link` | isReject/isMustPass/conditionCn |
| wf_node_field_perm | `wf:node` 下 `wf:fieldPerm` | field/perm |
| wf_node_detail_perm | `wf:node` 下 `wf:detailPerm` | dtKey/field/perm |
| wf_node_detail_filter | `wf:node` 下 `wf:detailFilter` | dtKey/rowFilter |
| wf_node_timeout | `wf:node` 下 `wf:timeout` | 多条 |
| wf_custom_action | `wf:node` 下 `wf:customAction` | actionKey/name/type/url |
| wf_custom_operation(+right) | `wf:node` 下 `wf:operation` + `wf:right` | btnName/actionType + 权限 |
| wf_process_definition | 流程级 `wf:processMeta` | formId/layoutId（defKey 经 `flow_def_bridge` 桥接） |
| wf_workflow_type / wf_definition_gray | `wf:processMeta` 的 workflowType/grayEnabled | — |

> 运行期 3 张（wf_instance/wf_task/wf_approval_log）**不在本回填范围**，属 P3。

## 2. 回填策略（一次性迁移 Job）

新建迁移组件（如 `WfDefinitionBackfillJob`），在应用启动后由运维手动触发（或带开关的 `@Scheduled` 一次性任务）：

1. 遍历 `wf_process_definition` 全部有效记录；
2. 取每条对应的已部署 BPMN（`ACT_GE_BYTEARRAY`，经 `repositoryService.getBpmnModel(defId)`）；
3. 按 `node_key` 从 `wf_process_node` + 关联表读取该定义全部定义期语义；
4. 用 `BpmnExtensionUtil.writeNode / writeLink / writeProcessMeta` 把语义写回 `BpmnModel`；
5. **重新部署**该 `BpmnModel`（`repositoryService.createDeployment()...deploy()`），产生**新版本**（保留旧版本以便回滚与历史实例还原，见分析 §12.9.4）；
6. 在 `flow_def_bridge` 写入 `def_key ↔ 新引擎定义` 映射（D6）；
7. 标记该 `wf_process_definition` 已回填（避免重复）。

> 关键约束：重新部署会生成**新版本**。旧版本不得删除（仍被历史实例引用，分析 R6），回填仅"追加新版本 + 桥接"。前端设计器后续以新版本为准。

## 3. 双轨对账（只读告警，不阻断业务）

回填后保留 `wf_*` 定义期表**只读**，运行 `WfDefinitionReconcileJob` 周期比对：

- 对每条已回填定义，分别从「引擎 BPMN 扩展」与「wf_* 源表」读取节点/操作者/权限集合；
- 做集合差异（nodeKey 维度），不一致则写告警日志 / 通知，**不自动修复、不改写**；
- 直到对账通过率 100% 且观察期满，再进入 P3 关闭双轨。

## 4. 风险与回退

- **回退**：回填仅新增引擎版本 + 桥接，不改写旧数据与旧版本；回退 = 前端/接口切回旧 `wf_process_definition`（桥接失效即可）。
- **R6（定义删除致历史语义丢失）**：回填期立运维禁令——禁止删除仍被引用的旧流程版本。
- **幂等**：回填按 `wf_process_definition.id` 去重标记，重复执行安全。
