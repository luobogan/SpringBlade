# 泛微 E9 · 分权（数据隔离）统一收口方案

> 针对登记册中一类**共性根因**的系统性整改设计：各模块各自实现分部数据隔离，导致
> （a）**开关耦合**——FNA 用 `isUseWfManageDetach`（workflow 开关）门控财务数据（FNA-N1）；
> （b）**手工样板**——FNA 16+ 端点、cube 多端点重复 `if(isUseXxxDetach && uid!=1){…}`（FNA-N3、cube 同类）；
> （c）**缓存 key 缺陷**——cube `DetachHelper` 漏 `rightStr`（DET-P0-2）；
> （d）**共享体系缺强制**——CRM 依赖每端点接入 `CRM_ShareInfo`（CRM-N1）；
> （e）**SQL 拼接**——`GetAppListCmd` 拼接整数分部 ID（CUBE-N1）。
> 目标：一处定义、自动注入、统一缓存、强制校验。

---

## 1. 设计原则

1. **开关与端点解耦**：「用哪个分权开关」由中央注册表决定，端点不再硬编码 `isUseXxxManageDetach`。
2. **自动注入**：分部过滤经拦截器自动叠加到查询，消除逐端点样板与「漏加即暴露」。
3. **单一真相源**：允许分部列表只由一个 `DetachScopeResolver` 计算，缓存 key 含完整维度。
4. **参数化优先**：分部 ID 一律走 `PreparedStatement` 占位，杜绝拼接。
5. **共享体系并列治理**：CRM 类记录级共享，用对称拦截器强制共享视图，而非套用分权开关。

---

## 2. 统一收口架构

```
┌─────────────────────────────────────────────────────────┐
│  ModuleDetachSwitch 注册表（模块→开关方法 唯一映射）        │
│   WORKFLOW→isUseWfManageDetach  FORMMODE→isUseFmManageDetach│
│   FINANCE →isUseFnaManageDetach(新增)  HR→isUseHrmManageDetach│
│   CRM     →NONE（走共享拦截器）                            │
└───────────────┬─────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────┐
│  DetachScopeResolver.getAllowedSubcompanies(user,module,rightStr)│
│   · 开关关 → 返回 {-1}（调用方按「不受限」解释）            │
│   · 开关开 → SysRoleSubcomRight 取角色→分部，返回 int[]      │
│   · 缓存 key = uid + "_" + module + "_" + rightStr（修 DET-P0-2）│
└───────────────┬─────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────┐
│  @DetachScope(module=, right=) 注解 + ContainerRequestFilter │
│   解析 allowed → 注入 QueryContext.subcompanyFilter          │
│   所有列表查询经 SubcompanyAwareSql 自动追加                  │
│   `AND subcompanyid IN (?,?,...)`（参数化，修 CUBE-N1）     │
└─────────────────────────────────────────────────────────┘
```

## 3. 核心组件（代码草案）

### 3.1 开关注册表
```java
public enum ModuleDetachSwitch {
    WORKFLOW("workflow", m -> m.isUseWfManageDetach()),
    FORMMODE("formmode", m -> m.isUseFmManageDetach()),
    FINANCE ("finance",  m -> m.isUseFnaManageDetach()), // 新增方法
    HR      ("hrm",      m -> m.isUseHrmManageDetach()),
    CRM     ("crm",      null);                          // 走共享拦截器
    // ...
}
```

### 3.2 统一解析器（修复 DET-P0-2 缓存 key）
```java
public final class DetachScopeResolver {
    private static final Map<String,int[]> CACHE = new ConcurrentHashMap<>();
    public static int[] getAllowedSubcompanies(User u, ModuleDetachSwitch m, String rightStr){
        String key = u.getUID()+"_"+m.name()+"_"+rightStr;   // 含 rightStr
        return CACHE.computeIfAbsent(key, k -> {
            ManageDetachComInfo mdc = new ManageDetachComInfo();
            if(m.switchFn==null || !m.switchFn.test(mdc)) return new int[]{-1};
            // 角色→分部
            return new SysRoleSubcomRight().getSubComByUserRightId(u.getUID(), rightStr, 0);
        });
    }
}
```

### 3.3 参数化分部过滤（修复 CUBE-N1）
```java
public class SubcompanyAwareSql {
    public static String appendIn(String col, int[] subs){
        if(subs.length==1 && subs[0]==-1) return "";          // 不受限
        return " AND "+col+" IN ("+repeat("?", subs.length)+")";
    }
    // PreparedStatement 绑定 subs
}
```

### 3.4 自动注入拦截器（消除 FNA-N3 样板）
```java
@DetachScope(module=ModuleDetachSwitch.FINANCE, right="FNA:VIEW")
public class GetFnaVoucherListCmd extends AbstractCommonCommand<...> {
    // 不再手写 if(isUseWfManageDetach && uid!=1){...}
    // 拦截器注入 QueryContext.subcompanyFilter，DAO 自动拼接参数化 IN
}
```
> 拦截器在 `CommandContext`/JAX-RS `ContainerRequestFilter` 读取注解 → 调 `DetachScopeResolver` → 写入 `QueryContext`；管理员（`uid==1`/sysadmin）跳过。

### 3.5 CRM 共享强制拦截器（治理 CRM-N1）
```java
@CrmShareScope(objectType="customer")
public class CrmCustomerListCmd ... {
    // 拦截器强制叠加 CRM_ShareInfo 派生视图（crmShareBase.getShareSql）
    // 任何读端点不加注解即无法访问 CRM 数据 → 杜绝漏接
}
```

## 4. FNA 落地改造（直接修复 FNA-N1/N2/N3）

1. **FNA-N1（开关耦合）**：`ManageDetachComInfo` 新增 `isUseFnaManageDetach()`（或复用全局 `isUseManageDetach()`）；将 FNA 16+ 端点的 `isUseWfManageDetach` 改为走 `ModuleDetachSwitch.FINANCE`（经注册表）。明确开关关闭时 FNA 语义（建议「受限空结果」而非「全量」）。
2. **FNA-N2（注入）**：`BankEnterpriseUtil.java:8601` 的 `workflowId` 改为参数化；`GetAddConnectPageCmd:332` 的 `xssUtil.put(sqlWhere)` 改为 SQL 转义/参数化。
3. **FNA-N3（样板）**：给 FNA 列表 Cmd 加 `@DetachScope(module=FINANCE)`，删除手工 `if` 样板，由拦截器注入。
4. 验证：补充「workflow 分权关 / 财务分权开」组合单测，确认财务数据不跨分部暴露。

## 5. 迁移路径（分批）

| 批 | 内容 | 覆盖项 |
|---|---|---|
| 1 | 新增 `ModuleDetachSwitch` + `DetachScopeResolver` + `SubcompanyAwareSql`；修 `DetachHelper` 缓存 key | DET-P0-2、CUBE-N1 |
| 2 | FNA 16+ 端点改造（注册表 + 注解 + 参数化） | FNA-N1/N2/N3 |
| 3 | cube 端点接拦截器（去手工样板） | cube 同类样板 |
| 4 | CRM `@CrmShareScope` 强制共享视图 + 专项审计 | CRM-N1 |
| 5 | workflow/HR 等其余模块接入注册表（消除散落 `isUseXxxManageDetach`） | 长期一致性 |

---

## 6. 验证矩阵

| 场景 | 期望 |
|---|---|
| 开关关 + 普通用户 | 返回 `{-1}` → 受模块语义约束（财务=空，而非全量） |
| 开关开 + 有授权分部 | `IN(授权分部)` |
| 同 user+subcompany + 不同 rightStr | 缓存不串（key 含 rightStr） |
| 管理员 uid==1 | 跳过过滤 |
| CRM 端点无 `@CrmShareScope` | 编译/启动期校验阻断（防漏接） |

---

## 7. 影响面与风险

- **影响面**：触及所有分权/共享模块端点，属架构级改造，需回归测试覆盖各模块列表/导出/统计。
- **风险**：注册表开关映射错误会导致整模块数据可见性翻转——上线前须以「开关 × 角色 × 模块」矩阵全量验证。
- **渐进式**：拦截器与手工 `if` 可并存过渡，逐模块切换，避免一次性大改。
