# 流程版本控制设计与改造说明

> 适用页面：`/formmode/workflowdesign?defId=xxx`（流程设计器）
> 参考对象：ecology `WorkflowVersion`（`workflow_base.version / activeVersionID / isvalid` 版本组模型）+ Flowable 原生部署版本（`ACT_RE_PROCDEF.key + VERSION_`）
> 完成日期：2026-09-13

## 1. 版本模型

采用 **E9 版本组锚点 + Flowable 原生部署版本** 的双层模型：

| 层 | 载体 | 规则 |
|---|---|---|
| 业务版本（v1/v2/v3…） | `wf_process_definition.version` | 同 `proc_key` 组内递增（`uk_proc_key_version` 唯一键保证不撞）；另存新版本 = max+1，status=0 草稿 |
| 版本组锚点 | `wf_process_definition.active_version_id`（本次新增） | 组内**每行**都指向「当前激活版本」的 defId；首版=自身 id；NULL=单版本流程（组=自身，`anchorOf()` 兜底） |
| 引擎版本 | Flowable `ACT_RE_PROCDEF.VERSION_` | 同 procKey 每次 deploy 自动 +1，与业务版本并行；**在途实例绑定创建时的 `ACT_RE_PROCDEF.ID_` 原生隔离，新版本不影响运行中流程** |

版本组查询（对齐 ecology `WorkflowVersion.getAllVersionList`）：
`active_version_id = :anchor OR id = :anchor ORDER BY version`。

与 E9 的对照：E9 用 `workflow_base.activeVersionID` 串组、`isvalid 1活动/2测试/3非活动`；本项目用 `activeVersionId` 串组、`status 0草稿/1已发布/2停用`（含测试态时可在 status 语义上扩展）。

## 2. 交互逻辑（版本创建 / 保存 / 展示 / 切换）

| 动作 | 交互 | 实现 |
|---|---|---|
| **创建新版本** | 「另存为新版本」按钮（流转设置页签栏右侧 / 基础设置表单）→ 生成 v+1 **草稿** → **自动跳转**到新版本（`history.push(?defId=新id)`）继续设计 | `POST /definition/{id}/version` |
| **保存** | 各版本行独立保存（与 E9 一致：历史版本亦可编辑，非不可变快照）；激活版本决定新发起实例走哪一版 | 既有 saveBpmn/updateNode 等 |
| **展示** | ① 流转设置页签栏右侧版本工具条：版本下拉（v{n} + 草稿/已发布/停用 Tag + 金色「激活中」标记）；② 流程卡片「版本」行：v{n} + 激活中/非激活 Tag | `GET /definition/{id}/versions` |
| **切换** | 下拉选版本 → 跳转该 defId → 页面按 URL 自动选中并打开流转设置 | 前端 `history.push` |
| **发布并激活** | 「部署」= 发布即激活：本版本 status=1 + 部署 Flowable + **组内锚点统一切到本版本** + 同组其它「已发布」版本自动转停用 | `POST /definition/{id}/deploy`（已增强） |
| **版本回退** | 对历史版本再次「部署」即重新激活（锚点切回；旧激活版本转停用）；新发起实例走回退后的版本，在途实例不受影响 | 同上 |
| **差异查看** | 「版本对比」按钮 → 弹窗选目标版本 → 展示节点/出口的 新增/删除/修改 三类差异 | `GET /definition/{id}/version/diff?targetId=` |

## 3. 版本号生成规则

1. 新版本 = `version + 1`（同 procKey 组内最大值 +1），**由数据库唯一键 `uk_proc_key_version(proc_key, version)` 兜底防并发重号**；
2. 新版本一律 `status=0` 草稿，不影响当前激活版本；
3. 引擎侧版本由 Flowable 在 deploy 时自动管理，不与业务版本强绑定展示。

## 4. 历史版本留存与访问方式

- **留存**：每个版本是 `wf_process_definition` 独立一行（含各自的 `bpmn_xml` 快照），子表（节点/出口/字段权限/明细权限/操作者）随版本完整复制，互不影响；
- **访问**：版本下拉任意切换查看；差异对比随时可看；
- **节点布局（form_layout）**：按 `(formId, nodeKey)` 存储、与 defId 无关，nodeKey 跨版本不变 → **布局天然随版本共享**（属预期行为：布局跟表单走，不跟定义版本走）。

## 5. 版本对比（差异展示）

维度（`VersionDiffVO`）：

- **节点**：按 `nodeKey` 匹配 → 新增 / 删除 / 修改（名称、类型、会签关系）；
- **出口**：按 `fromNodeKey→toNodeKey` 匹配 → 新增 / 删除 / 修改（条件中文、条件表达式、退回线、必经分支）；
- 前端 `VersionDiffModal`：双列对照（当前版本 vs 对比版本）+ 差异 Tag（绿新增/红删除/橙修改），节点/出口两页签。

## 6. 激活/回退处理策略

| 事项 | 策略 |
|---|---|
| 激活前提 | 该版本必须有 `bpmn_xml`（deploy 校验）；草稿发布即激活 |
| 锚点切换 | 组内所有行 `active_version_id` 统一指向新激活版本（`promoteActiveVersion`，仅变更行落库） |
| 状态联动 | 新激活版本 status=1；同组其它 status=1 版本 → 2 停用；草稿保持草稿 |
| 在途实例 | Flowable 原生隔离（实例绑定旧 procDefId 继续跑），**不做**实例迁移；如需把在途实例迁到新版本，后续可用 `ProcessInstanceMigration` 扩展 |
| 待办/已办 | 不迁移（历史任务属于旧版本节点，审计留痕） |
