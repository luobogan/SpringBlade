## 3. 后端已就绪的接口契约（前端直接对接）
基址前缀：`/api/blade-workflow`（下面省略）。返回统一 `R{code,success,data,msg}`，分页为 `data{records:[...],total,current,size}`。

### 3.1 待办/已办/我的请求（WfOdocTodoController，`/odoc`）
- `GET /odoc/todo`、`GET /odoc/done`、`GET /odoc/my-request`
- Query：`officalType`(1发文/2收文/3签报)、`title`、`secretLevels`(数组)、`beginTime`、`endTime`、`current`、`size`（`assignee` 仅管理员）
- 行 `OdocTodoVO`：`taskId, instanceId, defId, officalType, title, issuedNum, receiveNum, issuedUnit, receiveUnit, secretLevel, urgency, topicType, writtenDate, issuedDate, docId, currentNodeKey, starter, taskStatus, receiveTime, operateTime`
- 办理/退回/转办等动作**复用通用** `/api/blade-workflow/task/**`（`/task/{id}/approve|reject|forward|...`），不要在公文页重造。

### 3.2 督办（WfOdocSuperviseController，`/odoc/supervise`）
- `GET /supervise/setting?defId` / `POST /supervise/setting`（upsert）
- `GET /supervise/list`（`officalType, superviseType`(0我发起的督办/1我被督办)`, status, current, size`）
- `GET /supervise/count`（角标，督办中数量）
- `POST /supervise`（`{instanceId, supervisorId?, deadline, remark}`）
- `POST /supervise/{id}/remind`
- 行 `OdocSuperviseVO`：`id, instanceId, defId, officalType, title, issuedNum, supervisorId, starterId, status(0督办中/1已办结/2已取消), deadline, remark, lastRemindTime, createTime`

### 3.3 统计 / 监控（WfOdocReportController，`/odoc`）
- `GET /report/statistics?officalType` → `OdocStatisticVO[]`：`{officalType, total, running, approved, rejected, canceled, suspended, draft}`（按类型汇总，ECharts 可用）
- `GET /monitor/list`（`officalType,title,current,size`）→ 在途公文分页（**仅流程管理员**，返回同 `OdocTodoVO`）；管控动作复用 `/api/blade-workflow/instance/**`（`/{id}/withdraw|stop|resume|cancel`）

### 3.4 文种转换（WfOdocDocTypeChangeController，`/odoc/doc-type-change`）
- `GET /setting?defId` / `POST /setting` / `DELETE /setting/{id}`
- `GET /assignment?defId` / `POST /assignment`（文种变更次数限制：`docTypeChangeNumber` 1不限/2一次/3自定义 + `docTypeChangeTimes`）
- `GET /revision?instanceId`（变更记录）
- `POST /submit`（`{instanceId, targetDefId, reasons}`）→ 记录变更 + 更新镜像 officalType
- `WfOdocDocTypeChange`：`id, defId, targetDefId, targetOfficalType, isDefault, fieldMaps(JSON), enabled`

### 3.5 交换（WfOdocExchangeController，`/odoc/exchange`）
- 内部：`POST /inner/send`（`{instanceId, targetUnits:[], remark}`）、`GET /inner/list?direction&officalType&current&size`、`POST /inner/{id}/receive`
- 外部：`GET /external/available`（false 时前端隐藏入口）、`GET|POST /external/setting`、`DELETE /external/setting/{id}`、`POST /external/send?platformCode&instanceId`（未接入适配器时后端明确报错）
- `WfOdocExchangeInner`：`id, instanceId, officalType, direction(1发/2收), targetUnit, documentIdentifier, issuedNum, issuedUnit, exchangeStatus(0待接收/1已接收/2已退回), remark`

> - `docTypeChange` 末段 `doctypechange` 里的 `Doc/Type/Change` 不在 `commonWords` 词典（补词典会误伤含 `doc`/`type` 子串的其它路径），故在 `app.tsx` 的 `PAGE_DIR_ALIAS` 显式登记 `'odoc/doctypechange' → 'DocTypeChange'`（key 经 `normalizeDirKey` 去连字符，连字符/驼峰菜单 path 都能命中）。
> - DB 菜单记录已按上表 camelCase path 建（迁移 010）。**改 path 后前端路由随之失效，务必同步 `blade_menu.path`**。
>
> 路由说明：`app.tsx` 的 `buildComponentLoaders` 对 2 段菜单 path `/odoc/x` 只解析 `./pages/Odoc/<Pascal>/index.tsx`（约定③）或 `./pages/Odoc/<Pascal>/<Pascal>.tsx`；扁平 `pages/Odoc/X.tsx` **不会**被命中。故每个页面配了目录入口 `index.tsx`（re-export 扁平实现）。菜单为 DB 配置（后端菜单驱动），按上表 path 建菜单记录即可挂载。
