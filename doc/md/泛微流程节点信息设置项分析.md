### 2.4 关键细节与坑

1. **`objid + isnode` 是复合归属**：同一张表同时存「节点操作」「出口规则」，查询时必须两个条件一起用。
2. **`type` 有 4 种取值**（0/1/2/3），而配置 UI 上只呈现 2~3 类；`type=2`（外部接口 `action.*`）与 `type=3`（DMLAction）在运行时走两套完全不同的执行分支。
3. **`ispreadd` 复用为「前后」标记**，而在自定义动作的挂载记录里它又是 `ispreoperator`（前/后）——同一个字段两种语义，靠 `type` 区分。
4. **`operateorder` 排序对 NULL 特殊处理**：`CASE WHEN operateorder IS NULL THEN -1`，历史数据（NULL）会被排到最前，做迁移时要留意。
5. **「退回时触发」是双向的**：`istriggerreject`（附加操作表）+ `drawbackflag`（动作表），漏掉任一个都会导致退回时不执行。
6. **顺序**：节点前操作按 `operateorder` 升序执行，且**在同一节点内**；跨节点的执行顺序由流程流转决定。

### 13.10 关键细节与坑

1. **字段权限是「三列 × 0/1/2/3」而不是单一 `fieldAttr`**：`isview` / `isedit` / `ismandatory` 各自独立，`2/3` 表示「禁用」（值仍保留），前端再折算成勾选态 + 禁用态。SpringBlade 的 `perm` 单值 0/1/2/3 是**把三列压缩成一列**，属于有损映射（见 13.11）。
2. **`workflow_nodeform` 与 `workflow_nodeform_form` 是孪生表**，靠 `nodeid == -12345` 区分（`FormTemplateManager.java:22`）；明细侧同理（`workflow_NodeFormGroup` ↔ `workflow_nodeformgroup_form`）。
3. **归档节点强制只读**（`GetNodeFieldInfoCmd.java:177-178`）。
4. **负 fieldid 是「虚拟字段」**（标题/紧急程度/短信提醒/签字意见/微信提醒/打印次数），不走表单字段表。
5. **显示项分两套字段**：显示侧 `showdesc/signshowdesc/selectformat`，打印侧 `printshowdesc/printsignshowdesc/printselectformat/printviewtype/printviewdesc`；打印还多一个 `oldvalue`（沿用显示模板）。改显示忘了打印会出现「屏幕对、打印不对」。
6. **`showdesc` 存 JSON + Base64 双重编码**，直接读库看到的是编码串。
7. **`vt*` 与 `vd*` 是两级**：`vt*` 决定「哪些类型的意见参与显示」，`vd*` 决定「每条意见里显示哪些列」。容易只改前者导致看不到内容。
8. **`remarkcolumn` 有 1/2/3 三档**，打印侧 `PRINTREMARKCOLUMN` 是它的镜像。
9. **同步逻辑三套且陷阱不同**（尤其 html 模式必须传 `toexcel=-1`）。
10. `GetNodeAdviseCmd` 名字误导：是「打印模板的节点意见显示设置」，不是「必填/说明」。

### 14.11 关键细节与坑（含疑似缺陷）

1. **「默认签字意见」用 `menutype = -菜单id` 这个负值编码**，且存在 `workflow_nodeCustomNewMenu`（不是 rcmenu）。任何「查询菜单配置」的语句都要同时考虑正/负 menutype。
2. **反馈控制 `Ctrl=2` 时必须回读旧名**，否则「不需反馈」名称被覆盖成空。
3. **菜单排序只影响新引擎办理页**（`GetRightMenuCmd`），经典 `RequestMenu` 串是硬编码顺序（14.5 强证据）。
4. **自定义操作的权限判定是「字符串相等」**（`operatortype + "" + location` == `status`），新增操作主体/位置时必须同步维护 `getUserStatusByRequestid` 的取值，否则按钮永不显示。
5. **自定义操作「流程操作」类型唯一且强制最后**。
6. **占位符协议 `$fieldname$`（配置期）→ `{fieldid}`（运行期）**，只对 `cusopttype=0`（打开 URL）做替换。
7. **`isDisableShare` 是反向开关**（置 1 = 禁用分享）。
8. **`SaveTakingMenuCmd` 无独立 Get**，读取侧在主入口。
9. **「同步至所有节点」有 5 套实现**，其中「节点级整行复制」还会连带复制自定义操作/文档比对/新建流程的明细表——漏了会出现「按钮在但点了没动作」。
10. **疑似缺陷（仅代码观察，供排查时警惕）**：
    - `GetOperationMenuInfoCmd.java:729` 与 `:737`：意见征询「反馈控制」两个分支都写到 `ccsubnobackMenuSet`，疑应为 `takingOpinions*`。
    - `SaveOperationMenuCmd.java:795`：`insert into workflow_nodeCustomNewMenu(...)` 值列表出现**双逗号**（位于 `id<=0` 分支，正常流程不会进入）。
    - `SaveOperationMenuCmd.java:760-764`：`buttonNameId = rs.getInt("id")` 用的是外部 `rs` 而非刚查询的 `rsz`。
    - `SaveBackNameMenuCmd.java:200-208`：`takingForward` insert 分支列 13 个而 values 11 个，数量不匹配。
    - `case 30`（征询转办）**没有** `insertSql` 插入默认签字意见行，与其它 case 不对称。
    - `haschuanyueback` / `haschuanyuenoback` 有写入（`:476-487`）但 Get 侧未读取，运行时消费者未找到。
