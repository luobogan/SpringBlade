# 收发文落地设计：编辑器选型与套红合成

> 上游文档：《泛微E9-收发文与正文套红功能分析及SpringBlade落地方案.md》§11–§13。
> 本文将其中的 **P1（正文编辑器选型）** 与 **P3（套红合成）** 展开为可执行设计：选型矩阵与决策、数据表 DDL、套红状态机、接口契约、合成引擎、与现有体系的集成点。
> 目标读者：后端（blade-workflow / blade-formmode）、前端（ant-design-pro）、运维。
> 约定：表名前缀 `wf_odoc_`；业务字段与项目一致补齐 `tenant_id / create_user / create_time / update_user / update_time / is_deleted / status`。
>
> ⚠️ **权威基准（以此为准）**：套红技术的标准形态是「**GB/T 9704 标准底座 + OFD/PDF 版式文件载体 + AI 智能排版 + CA 电子签章**」的一体化解决方案，详见《收发文落地-版式文件OFD-PDF电子公文方案.md》。
> 因此，本文的「docx + 书签套红」方案定位为**企业内部轻量公文 / 移动端兜底 / 存量兼容的过渡形态**，不是政务公文的目标形态；政府 / 国企场景必须在本文 P3 之后**叠加版式文件路线**（含 GB/T 9704 规则库、AI 排版、CA 签章、OFD-A 归档）。

## 一、P1 正文编辑器选型

### 1.1 需求矩阵（收发文正文的能力底线）

| # | 能力 | 用途 | 是否硬性 |
|---|---|---|---|
| N1 | 打开/另存 `.docx` | 正文载体 | **硬性** |
| N2 | 读写 **Word 书签** | 套红替换文号/主送/抄送，`Content` 插入正文 | **硬性** |
| N3 | **修订留痕（track changes）+ 接受修订/清稿** | `isCompellentMark`、套红前清稿 | **硬性**（政务） |
| N4 | docx → PDF | 在线预览 | **硬性** |
| N5 | docx → OFD | 国标归档 / 信创 | 条件硬性（政务） |
| N6 | 移动端可用 | 手机办理 | 硬性 |
| N7 | 私有化部署 | 政企内网 | 硬性 |
| N8 | 版本另存（每次保存/套红生成新版本） | 取消套红回滚 | **硬性** |
| N9 | 与表单字段互通（标题/文号回写） | 表单↔正文联动 | 硬性 |
| N10 | 授权成本 | 预算 | 重要 |

### 1.2 三方案对比

| 维度 | A. OnlyOffice Docs Server | B. WPS Web 开放平台 / 永中 | C. 自研「HTML → docx」 |
|---|---|---|---|
| N1 docx 编辑 | ✅ 原生 | ✅ 原生（商用） | ⚠️ 需 HTML→docx 转换（E9 已有 `convertHtmlToDocx` 先例） |
| N2 书签 | ✅ DocumentBuilder 可读写书签 | ✅ | ⚠️ 服务端替换（可行，但前端不可见） |
| N3 修订留痕 | ✅ 原生 track changes | ✅ | ❌ **无**（需自研意见式痕迹） |
| N4 PDF | ✅ 内置转换 | ✅ | ✅（LibreOffice/转换服务） |
| N5 OFD | ⚠️ 需插件/外部转换 | ✅（国产化支持好） | ⚠️ 需外部转换 |
| N6 移动端 | ✅ 响应式 | ✅ | ✅（FluentEditor 已适配 ≤768px） |
| N7 私有化 | ✅ 开源（AGPL） | ⚠️ 商业授权 | ✅ |
| N8 版本 | ✅ 回调落文件即版本 | ✅ | ✅ |
| N10 成本 | 低（自建，注意 AGPL） | 中~高（授权） | 低（开发成本高） |
| 与 E9 对齐度 | 高 | **最高**（E9 的 WPS 路径） | 中（E9 的无插件路径） |

### 1.3 决策建议（分层混搭，不赌单一方案）

```
主编辑器（PC 办理/设计）：OnlyOffice Docs Server
  └─ 满足 N1/N2/N3/N4/N6/N7/N8；AGPL 需法务确认（政企私有化通常可接受，必要时采购商业授权）

国产化/OFD 输出：外部转换服务
  └─ docx → PDF / OFD 用 LibreOffice headless 或 WPS Linux 转换（对齐 E9 weaver/wps/view/linux/convert）

移动端/轻量公文：自研 HTML → docx（方案 C 作为兜底）
  └─ 复用现有 RichTextEditor(@opentiny/fluent-editor) 采集 HTML
  └─ 服务端 convertHtmlToDocx 后走同一套套红合成（对齐 E9 onlineEditStore.previewWithTempl 路径）
  └─ 明确不接受"修订留痕"，仅用于简报/通知类轻公文
```

**决策 checklist（P1 启动前必须答完）**
1. 是否需要修订留痕？→ 是：排除纯 C 方案。
2. 是否必须 OFD 归档？→ 是：确认 A 的 OFD 转换链或引入 B。
3. AGPL 是否可接受？→ 否：转 B 或采购 OnlyOffice 商业授权。
4. 移动端是否要编辑正文？→ 是：C 兜底方案必须一起做。

### 1.4 与现有正文区的衔接（前端）

- 正文区容器：沿用流程表单布局（`ExcelPreview` 已支持 PC 表格 / ≤768px 列表化），在布局中以「正文字段」占位（建议新增 `fieldHtmlType=9 公文正文`，见 §2.3）。
- PC：`fieldHtmlType=9` 渲染 OnlyOffice iframe（`/web-apps/apps/documenteditor/index.html` + `callbackUrl` 指向 blade-workflow）。
- 手机：同一字段降级为 `RichTextEditor`（compact）+ 「在 PC 端编辑正文」提示，或直接只读展示 PDF。
- 保存回调：OnlyOffice `callback` → `PUT /api/blade-workflow/odoc/doc/{docId}/version/callback` → 落新版本（对齐 §3.4）。

## 三、套红状态机

### 3.1 状态定义

| 状态 | 含义 | 落库表现 |
|---|---|---|
| `S0 无正文` | 尚未创建正文 | `wf_odoc_doc` 无记录 |
| `S1 未套红` | 有正文，未套红 | `doc.has_used_templet=0`，最新版本 `has_used_templet=0` |
| `S2 已清稿` | 已生成"套红前取消痕迹版本" | 新增版本 `has_used_templet=0`，`version_detail='套红前取消痕迹版本'` |
| `S3 已套红` | 套红完成 | `doc.has_used_templet=1`，最新版本 `has_used_templet=1` |
| `S4 已取消` | 回滚到未套红版本 | 新增版本 `has_used_templet=0`，`doc.has_used_templet=0` |

### 3.2 状态转移

```
S0 --创建正文--> S1
S1 --进入套红节点且未套红--> S2(清稿) --> S3(套红)
S3 --取消套红--> S4  (S4 ≡ S1 语义, 但保留版本痕迹)
S1 --非套红节点保存--> S1(新版本, has_used_templet=0)
```

### 3.3 触发与拦截（对齐 E9）

```
自动套红条件（四者同时满足）:
  docId > 0
  AND currentNode == wf_odoc_process_set.taohong_node_key
  AND taohong_mould_id > 0 (或按权限/字段解析出 mouldId)
  AND doc.has_used_templet != 1

提交拦截（前端 + 后端双保险）:
  IF must_taohong = 1 AND currentNode == taohong_node_key AND has_used_templet != 1
     → 阻断提交, 提示「请先执行套红操作」
```

> 后端必须复检（对齐 E9 `RequestUseTempletManager.ifHasUseTempletSucceed`）：前端校验不可信，流转提交时由 `RequestManager` 等价物再判一次。

### 3.4 套红流程（服务端，逐步）

```
① 前置校验：docId / nodeKey / mouldId / has_used_templet / 正文类型可编辑(.doc/.docx/.wps)
② 清稿（若开启留痕）：acceptRevisions(最新版本) → 生成新版本 S2(has_used_templet=0)
③ 取书签值 Map：
     a. 读 wf_odoc_mould_bookmark(mould_id) → 书签清单
     b. 按 wf_odoc_mould_field_map(def_id, mould_id, select_value) 取 field_key
     c. 从 renderForm 的 dataJson（或 wf_form_snapshot）取字段值
     d. 日期按 date_show_type 格式化；金额按千分位
     e. 跳过 is_content=1 的书签（Content）
④ 合成：
     replaceBookmark(模板文件, 除Content外所有书签, bookmarkMap)
     insertContent(Content 书签, 正文文件内容)
     → 生成套红后 docx
⑤ 转预览：docx → PDF（必需）/ OFD（政务）
⑥ 落库：
     file_id = 上传(套红后docx)
     INSERT wf_odoc_doc_version(doc_id, version_id+1, file_id, has_used_templet=1, '套红版本')
     UPDATE wf_odoc_doc SET has_used_templet=1, doc_edition_id=新版本id
⑦ 返回 { versionId, previewUrl, fileId }
```

### 3.5 取消套红（版本回滚）

```
① 查最新未套红版本: SELECT * FROM wf_odoc_doc_version
     WHERE doc_id=? AND is_ext_file=0 AND has_used_templet=0 ORDER BY version_id DESC LIMIT 1
② 复制该版本文件为新版本（version_id+1，version_detail='取消套红回滚'）
③ UPDATE wf_odoc_doc SET has_used_templet=0, doc_edition_id=新版本id
④ 返回 { versionId, previewUrl }
找不到未套红版本 → 抛业务异常（对齐 E9 10005498）
```

## 四、接口契约

> 统一前缀 `/api/blade-workflow`（对齐现有 `WfDefinitionController`/`WfInstanceController` 风格）。

### 4.1 正文与版本

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/odoc/def/{defId}/doc` | 创建正文（由正文字段首次触发），返回 `docId` |
| GET | `/odoc/doc/{docId}` | 正文详情 + 最新版本 + `hasUsedTemplet` |
| GET | `/odoc/doc/{docId}/versions` | 版本列表 |
| POST | `/odoc/doc/{docId}/version` | 保存正文 → 新版本（`hasUsedTemplet=0`） |
| GET | `/odoc/doc/{docId}/preview?versionId=` | 取 PDF/OFD 预览 URL |
| PUT | `/odoc/doc/{docId}/version/callback` | **编辑器保存回调**（OnlyOffice callback）→ 落新版本 |

### 4.2 套红

| 方法 | 路径 | 请求体 | 返回 |
|---|---|---|---|
| GET | `/odoc/def/{defId}/doc/{docId}/taohong-info` | — | `{ isUseTempletNode, hasUsedTemplet, mouldId, mouldList, requiredBookmarks }` |
| POST | `/odoc/def/{defId}/doc/{docId}/taohong` | `{ mouldId?, cleanCopy? }` | `{ versionId, previewUrl, fileId }` |
| POST | `/odoc/def/{defId}/doc/{docId}/confirm-template` | `{ versionId }` | `{ success }`（可选，若需二次确认） |
| POST | `/odoc/def/{defId}/doc/{docId}/cancel-taohong` | — | `{ versionId, previewUrl }` |
| POST | `/odoc/doc/{docId}/clean-copy` | — | `{ versionId }`（清稿，独立能力） |

`taohong-info` 的 `mouldList`：按权限解析（对齐 `OdocTemplateSharedUtil.getCanUseTemplate`），管理员返回全部，其余按绑定范围过滤。

## 六、节点必做动作框架（套红/签章/清稿统一）

> E9 中套红、签章、清稿是三个独立 if；SpringBlade 建议抽象为统一框架，避免重复实现提交拦截。

```
NodeMandatoryAction（节点必做动作）
├─ actionType: TAOHONG(套红) / SIGNATURE(签章) / CLEAN_COPY(清稿)
├─ nodeKeys:   生效节点
├─ mustBeforeSubmit: 提交前是否强制完成
├─ stateResolver:   状态解析器（各自查自己的状态）
└─ onCompleted:     完成后的副作用（回写 has_used_templet / 签章记录 / 新版本）

流转提交时的统一复检（RequestManager 等价物）:
  for (action : currentNode.mandatoryActions) {
      if (action.mustBeforeSubmit && !action.stateResolver(instance)) {
          throw new ServiceException(action.blockMessage);   // 「请先执行套红操作！」
      }
  }
```

前端只需消费一个统一契约：`mandatoryActions: [{type, done, blockMessage, actionUrl}]`，按钮区按 `done` 渲染「去执行/已完成」。

## 八、验收清单

1. 新建发文实例 → 正文字段可创建正文，OnlyOffice 可打开/编辑/保存，**每次保存产生新版本**。
2. 进入套红节点 → 自动/手动套红成功；`fld_Mark`(文号)、`fld_zsdw`(主送)、`fld_csdw`(抄送)、`fld_yfrq`(印发日期) 书签值正确取自表单字段。
3. `Content` 书签正确插入正文，且**不被当作字段替换**。
4. 未套红时提交被拦截（前端 + 后端双重），提示「请先执行套红操作」。
5. 取消套红 → 回滚到未套红版本，`has_used_templet=0`，历史版本仍可查。
6. 套红前自动生成「套红前取消痕迹版本」（开启留痕时）。
7. 手机端（≤768px）正文降级为只读 + PDF 预览，不报错。
8. 测试流程（`is_test=1`）产生的正文/模板/合成产物可被一键清理，不污染正式数据。
9. 并发：同一正文同时触发两次套红，第二次被版本号/行锁挡住，不产生双版本错乱。
10. 政务场景：可输出 OFD，`.ofd` 只读展示正常。
