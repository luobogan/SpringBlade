# 数据范围五档值域与数据权限一致性方案

> 关联文档：
>
> - `SpringBlade/doc/md/权限配置分步向导与重复主体优先级分析.md`
>
> 本文只做方案分析，不改代码。

---

## 一、结论摘要

用户要求新增五档数据范围：

```text
1. 全部可见
2. 本人可见
3. 所在机构可见
4. 所在机构及子级可见
5. 自定义（权限值域）
```

其中自定义只支持：

```text
列 IN (数字列表)
列 = 数字
```

例如：

```sql
where scope.dept_id in (1,2)
where scope.dept_id = 1
```

这个方向是对的，而且当前项目里已经有了对应的统一解析器：

```text
org.springblade.system.datascope.DataScopeValueResolver
```

它的五档语义正好是：

```text
1 = 全部
2 = 本人
3 = 本部门
4 = 本部门及子级
5 = 自定义
```

而且自定义值域已经严格限制为：

```text
[where|and] [scope.]列 IN (纯数字列表)
[where|and] [scope.]列 = 纯数字
```

所以推荐原则是：

```text
不在建模数据范围里重写一套解析器；
直接复用 DataScopeValueResolver 的五档语义和自定义值域校验。
```

但要注意：现在建模数据范围和系统数据权限是两套机制，不能只在前端加一个下拉框就完事。

## 二、当前两套机制

### 2.1 系统数据权限：blade_scope_data

当前系统数据权限表：

```text
blade_scope_data
```

关键字段：

```text
resource_code
scope_field
scope_column
scope_type
scope_value
```

代码位置：

```text
blade-service/blade-formmode/.../FormDataServiceImpl.java:1487-1501
```

`ScopeRule` 内部类中明确注释：

```text
1全部 2本人 3本部门 4本部门及子级 5自定义
```

运行期统一调用：

```java
DataScopeValueResolver.resolve(
  rule.getScopeType(),
  rule.getScopeColumn(),
  rule.getScopeValue(),
  AuthUtil.getUser(),
  this::queryChildDeptIds
)
```

位置：

```text

```

处理规则：

- `UNRESTRICTED`：不过滤；
- `RESTRICTED`：生成 `列 IN (ids)` 过滤；
- `REJECTED`：追加 `AND 1=0`，无可见数据，fail-closed。

位置：

```text
FormDataServiceImpl.java:1358-1379
```

### 2.2 建模数据范围：modedatasharerule

当前建模数据范围表：

```text
modedatasharerule
```

字段：

```text

objtype       1角色 2部门 3岗位 4人员 5分部 7矩阵

```

代码位置：

```text
blade-service-api/blade-formmode-api/.../entity/ModeDataShareRule.java:33-79
```

当前运行期解析：

```text
ModeDataShareRuleServiceImpl.resolve()
```

位置：

```text
blade-service/blade-formmode/.../ModeDataShareRuleServiceImpl.java:68-135
```

当前逻辑是：

```text
当前用户命中某条共享规则
  → canViewAll=true
  → creatorSelf=1 时改为仅本人创建
  → 可选附加 rowCondition
  → 命中第一条就 return
```

也就是说当前建模数据范围表达不了：

```text
本人可见
所在机构可见
所在机构及子级可见
自定义列 IN 数字列表
```

它只能表达：

```text
某个授权对象命中后：全部可见 / 仅本人创建 / 附加结构化条件
```

### 2.3 两者当前优先级不叠加

表单数据列表：

```text
FormDataServiceImpl.pageFormDataByScope()
```

位置：

```text
FormDataServiceImpl.java:1162-1177
```

当前规则：

```text
配了建模权限 → 使用建模数据范围，不叠加 blade_scope
没配建模权限 → 回退使用 blade_scope 五档数据权限
```

所以：

```text
只在 blade_scope_data 里配置五档，不会自动影响已经配了建模权限的表单。
```

这是本次方案必须解决的核心点。

## 三、DataScopeValueResolver 是现成的统一口径

### 3.1 五档语义

代码注释位置：

```text
DataScopeValueResolver.java:32-59
```

语义：

| scopeType | 系统数据权限名称 | 建议界面名称 | 含义 |
|---|---|---|---|
| 1 | 全部 | 全部可见 | 不过滤 |
| 2 | 本人 | 本人可见 | 权限列 = 当前用户ID |
| 3 | 本部门 | 所在机构可见 | 权限列 IN 当前用户部门 |
| 4 | 本部门及子级 | 所在机构及子级可见 | 权限列 IN 当前部门+子孙部门 |
| 5 | 自定义 | 自定义 | 解析受限值域表达式 |

### 3.2 自定义值域限制

正则位置：

```text
DataScopeValueResolver.java:65-77
```

支持：

```text
where scope.dept_id in (1,2)
and scope.dept_id in (1,2)
scope.dept_id in (1,2)
where scope.dept_id = 1
scope.dept_id = 1
```

不支持：

```sql
where dept_id > 1
where dept_id in (select id from ...)
where 1=1
where name='abc'
where dept_id in ('1','2')
```

解析函数：

```text
DataScopeValueResolver.java:269-299
```

解析失败返回：

```text
REJECTED
```

调用方必须按：

```text
无可见数据
```

处理，不能降级为全部可见。

这是非常重要的安全设计。

## 四、推荐目标方案

### 4.1 总体原则

不要直接把建模数据范围替换成 `blade_scope_data`，也不要在建模侧重写一套五档解析。

推荐：

```text
建模数据范围表增加三列：
  scope_type
  scope_column
  scope_value

语义和解析器统一复用：
  DataScopeValueResolver
```

也就是：

```text
授权对象决定“谁”拥有这条规则
数据范围五档决定“这条规则能看到哪些行”
```

这两层要分开。

## 五、数据模型调整

### 5.1 `modedatasharerule` 增加字段

建议新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scope_type` | tinyint/int | 1全部 2本人 3所在机构 4所在机构及子级 5自定义；NULL=旧模型 |
| `scope_column` | varchar(100) | 行级过滤列；scope_type=2/3/4 必填；scope_type=5 可为空 |
| `scope_value` | varchar(2000) | 自定义值域；scope_type=5 必填 |

迁移脚本建议：

```sql
ALTER TABLE modedatasharerule
  ADD COLUMN scope_type tinyint NULL COMMENT '1全部 2本人 3所在机构 4所在机构及子级 5自定义；NULL=旧模型',
  ADD COLUMN scope_column varchar(100) NULL COMMENT '数据范围过滤列',
  ADD COLUMN scope_value varchar(2000) NULL COMMENT '自定义权限值域';
```

要做成幂等脚本，用 `information_schema.COLUMNS` 判断。

### 5.2 旧数据兼容

老数据：

```text
scope_type = NULL
```

继续走旧逻辑：

```text
命中授权对象 → canViewAll / creatorSelf / rowCondition
```

新数据：

```text
scope_type != NULL
```

走五档值域解析：

```text
DataScopeValueResolver
```

这样不会影响历史配置。

### 5.3 为什么不建议直接复用 blade_scope_data

原因：

```text
blade_scope_data 只表达“行范围”
modedatasharerule 还要表达“哪个授权对象拥有这条规则”
```

如果直接把建模数据范围写到 `blade_scope_data`：

- 授权对象信息丢了；
- 三步向导里的“当前授权对象类型”无法落地；
- 查看/维护两类建模权限不好区分；
- 现有建模权限优先于 blade_scope 的规则会被打破。

所以推荐：

```text
数据存在 modedatasharerule
语义复用 DataScopeValueResolver
```

## 六、五档数据范围如何映射

### 6.1 全部可见

配置：

```text
scope_type = 1
scope_column = 空
scope_value = 空
```

运行期：

```text
DataScope.canViewAll = true
```

不加行过滤。

### 6.2 本人可见

配置：

```text
scope_type = 2
scope_column = modedatacreator 或 modedatacreater
scope_value = 空
```

运行期：

```text
scopeColumn IN (当前用户ID)
```

注意当前建模主表实际创建人列有历史差异：

```text
modedatacreator
modedatacreater
```

建议运行期按物理表列自动选择，不要让用户手填：

```text
优先 modedatacreator
其次 modedatacreater
都没有 → REJECTED，无可见数据
```

### 6.3 所在机构可见

配置：

```text
scope_type = 3
scope_column = create_dept 或业务组织字段
scope_value = 空
```

运行期：

```text
scopeColumn IN (当前用户 dept_id 列表)
```

当前建模主表通常有：

```text
create_dept
```

如果业务表里还有：

```text
reqdept 经办部门
reqsub 经办分部
```

可以让用户在向导里选择。

建议默认值：

```text
create_dept
```

### 6.4 所在机构及子级可见

配置：

```text
scope_type = 4
scope_column = create_dept 或业务组织字段
scope_value = 空
```

运行期：

```text
scopeColumn IN (当前部门 + 全部子孙部门)
```

子部门展开复用：

```text
FormDataServiceImpl.queryChildDeptIds
```

当前 `DataScopeValueResolver.resolve()` 已经支持传入 `DeptDescendantProvider`。

### 6.5 自定义

配置：

```text
scope_type = 5
scope_column = 空
scope_value = where scope.dept_id in (1,2)
```

运行期：

```text
DataScopeValueResolver.parseCustomScope()
```

得到：

```text
column = dept_id
ids = [1,2]
```

再拼接参数化 SQL：

```sql
AND `dept_id` IN (?, ?)
```

如果配置：

```sql
where scope.dept_id = 1
```

得到：

```text
column = dept_id
ids = [1]
```

### 6.6 自定义值域必须检查目标表是否有该列

`dept_id` 只是用户给的例子。

当前实际表单物理表 `formtable_main_2` 里没有 `dept_id`，有：

```text
create_dept
modedatacreator
modedatacreater
```

所以：

```sql
where scope.dept_id in (1,2)
```

如果目标表没有 `dept_id` 列，运行期必须按：

```text
无可见数据
```

处理，而不是报错或直接放行。

前端最好给列选择器：

```text
只列出目标主表中的数字列
```

但自定义输入框仍允许手工填，最终以后端校验为准。

## 七、运行期解析改造

### 7.1 当前问题

当前 `ModeDataShareRuleServiceImpl.resolve()` 命中第一条就返回。

如果要支持多主体重叠、多规则命中，建议：

```text
旧模型保持首条命中；
新五档模型改为收集所有命中规则。
```

### 7.2 新模型聚合规则

对当前用户命中的多条新模型规则：

#### 如果有任一规则是“全部可见”

```text
最终 = 全部可见
```

#### 如果都是受限范围

按列合并：

```text
同列 → ids 求并集
不同列 → 多个 IN 条件 OR
```

例如：

```text
规则 A：create_dept in (100,200)
规则 B：create_dept in (300)
规则 C：modedatacreator = 6
```

最终 SQL：

```sql
AND (
  create_dept IN (100,200,300)
  OR modedatacreator IN (6)
)
```

#### 如果某条自定义规则解析失败

```text
该规则不授予任何数据
```

其它合法规则是否仍生效，建议：

```text
合法规则仍生效；
只有全部规则都无效时才无数据。
```

如果希望更严格，也可以配置为：

```text
任何非法规则都导致整体拒绝
```

这个需要业务确认。

### 7.3 DataScope VO 需要扩展

当前：

```text
DataScope
  canViewAll
  creatorId
  rowCondition
  sharedDataIds
  editableSharedDataIds
```

位置：

```text
blade-service-api/blade-formmode-api/.../vo/DataScope.java:8-52
```

建议新增：

```text
List<RowScope> rowScopes
```

结构：

```text
RowScope
  column
  ids
```

含义：

```text
多个 RowScope 之间 OR
同一个 RowScope 的 ids 之间 IN
```

这样五档模型和系统数据权限的行为就一致了。

## 八、SQL 过滤改造

当前建模数据范围 SQL 在：

```text
FormDataServiceImpl.java:1118-1122
```

现在只会：

```text
creator/shared 过滤
rowCondition 过滤
```

需要新增：

```text
appendRowScopes(scope, tableCols, countSql, dataSql, params)
```

要求：

1. 列名必须通过 `SAFE_COLUMN` 校验；
2. 列必须存在于当前主表；
3. ids 必须来自参数化值，不直接拼字符串；
4. 列不存在或 ids 为空时追加：
   ```sql
   AND 1=0
   ```
5. 多个 RowScope 用 OR 组合；
6. 与原有 rowCondition 是 AND 关系。

最终组合：

```sql
WHERE 1=1
  AND (rowScope1 OR rowScope2 ...)
  AND rowCondition
  AND 其它查询条件
```

### 与 blade_scope_data 的关系

保持当前优先级不变：

```text
配了建模权限 → 用 modedatasharerule 的 scope_type 五档
没配建模权限 → 用 blade_scope_data 五档
```

两边虽然表不同，但：

```text
编码一致
解析器一致
SQL 过滤方式一致
fail-closed 语义一致
```

这就叫“和数据权限那边设置一致”。

## 九、前端向导调整

### 9.1 第三步数据范围界面

在三步向导第三步中，每个授权对象配置一行：

```text
授权对象类型（顶部固定，不再每行选择）
授权对象（来自第 0 步选择）

权限列：根据数据范围动态显示/隐藏
权限值域：仅自定义显示
```

### 9.2 数据范围下拉

```ts
const DATA_SCOPE_TYPE_OPTIONS = [
  { value: 1, label: '全部可见' },
  { value: 2, label: '本人可见' },
  { value: 3, label: '所在机构可见' },
  { value: 4, label: '所在机构及子级可见' },
  { value: 5, label: '自定义' },

```

### 9.3 动态表单

| 数据范围 | 权限列 | 权限值域 |
|---|---|---|
| 全部可见 | 隐藏 | 隐藏 |
| 本人可见 | 默认创建人列，可改 | 隐藏 |
| 所在机构可见 | 默认 `create_dept` | 隐藏 |
| 所在机构及子级可见 | 默认 `create_dept` | 隐藏 |
| 自定义 | 隐藏 | 显示，必填 |

### 9.4 自定义输入提示

界面提示文案建议：

```text
仅支持：
列 IN (数字列表)
列 = 数字

例如：
where scope.dept_id in (1,2)

不支持子查询、字符串、函数或任意 SQL。
```

保存前可以做前端基础校验，但最终必须以后端 `DataScopeValueResolver.parseCustomScope()` 为准。

### 9.5 权限列来源

权限列建议从当前表单主表字段里取：

- 系统列：
  ```text
  modedatacreator
  modedatacreater
  create_dept
  ```

- 业务数字列：
  ```text
  workflow_billfield.fielddbtype in ('int','bigint','decimal',...)
  ```

只展示主表列。明细表字段不能作为当前列表行级过滤列。

## 十、后端校验

保存数据范围规则时必须校验：

### scope_type=1

```text
scope_column / scope_value 可忽略
```

### scope_type=2/3/4

```text
scope_column 必填
scope_column 必须是当前表单主表存在的数字列
scope_value 必须为空
```

### scope_type=5

```text
scope_value 必填
scope_column 可为空
```

调用：

```text
DataScopeValueResolver.parseCustomScope(scopeValue)
```

如果返回 `REJECTED`，直接拒绝保存并返回原因。

### type=2 维护权限

维护档也建议支持五档：

```text
查看范围：决定能看到哪些行
维护范围：决定能编辑/删除哪些行
```

但当前 `canMaintainAll()` 只返回布尔值，需要扩展成：

```text
可维护全部
或
可维护的 RowScope 列表
```

这是后续改造点，若不纳入本期，可先只支持查看档五档，维护档保持旧逻辑。

## 十一、与授权对象重叠规则的关系

用户先选授权对象类型，例如：

```text
人员 lh
```

那么第三步配置的是：

```text
lh 能看到哪些数据
```

如果另一个方案是：

```text
角色 部门领导
```

也命中 lh，并配置了另一个数据范围，那么最终合并：

```text
所有命中方案的可见数据做 OR
```

这和之前分析的 Ecology 规则一致：

```text
主体之间 OR
权限取 MAX
```

注意：

```text
授权对象类型不是优先级。
授权对象类型只是身份维度。
```

## 十二、实施顺序建议

### 第一阶段：兼容落地

1. `modedatasharerule` 增加三列；
2. 前端第三步加五档选择；
3. 后端保存时写入 `scope_type/scope_column/scope_value`；
4. 新规则运行期调用 `DataScopeValueResolver`；
5. 老规则 `scope_type=NULL` 保持旧行为。

### 第二阶段：运行期合并

1. `DataScope` 增加 `rowScopes`；
2. `ModeDataShareRuleServiceImpl.resolve()` 收集所有命中规则；
3. `FormDataServiceImpl` 拼接 OR 行过滤；
4. 支持重叠授权对象的 OR + MAX。

### 第三阶段：维护档五档

1. 把 `canMaintainAll()` 扩展为维护范围解析；
2. 编辑/删除时校验目标行是否在维护范围内；
3. 和查看范围共用同一套 `RowScope` 判定。

## 十三、验收场景

### 场景 1：全部可见

```text
授权对象：人员 lh
数据范围：全部可见
结果：lh 看到该表单全部数据
```

### 场景 2：本人可见

```text
授权对象：角色 部门领导
数据范围：本人可见
权限列：modedatacreator
结果：角色成员只看到自己创建的数据
```

### 场景 3：所在机构可见

```text
授权对象：人员 lh
数据范围：所在机构可见
权限列：create_dept
结果：lh 只看到 create_dept 属于自己部门的数据
```

### 场景 4：所在机构及子级可见

```text
授权对象：角色 部门领导
数据范围：所在机构及子级可见
权限列：create_dept
结果：看到当前部门及子孙部门的数据
```

### 场景 5：自定义 IN

```text
scope_value = where scope.dept_id in (1,2)
结果：只看到 dept_id 为 1 或 2 的数据
```

如果目标表没有 `dept_id` 列：

