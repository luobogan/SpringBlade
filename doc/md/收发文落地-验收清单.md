# 收发文一体化落地 — 验收清单（15 项）

> 适用范围：SpringBlade 收发文（发文 / 收文 / 签报）全链路，L1 开箱可用、L2 配置叠加。
> 关联文档：《收发文一体化技术方案.md》《收发文落地-编辑器选型与套红合成设计.md》《收发文落地-版式文件OFD-PDF电子公文方案.md》。
> 联调方式：dev 环境用 springblade-dev-login 技能取 sword-token 调 `/blade-workflow/odoc/**`；前端 umi dev（8000）走 `/api` 代理。
> 清理：所有 `is_test=1` 测试数据须可一键清理，不污染正式数据。

约定：流程定义与表单表关联——集团公司发文→`formtable_main_10`、集团部门收文→`formtable_main_11`、集团收文→`formtable_main_12`。

## L1 基础（默认开箱）

| # | 验收项 | 验收方法 | 通过标准 |
|---|---|---|---|
| 1 | 三套流程可导入且幂等 | `import_workflow.py` 对 dev 网关分别导入 `odoc_fawen/shouwen/qianbao`，各重复 2 次 | 每次 HTTP 200、`导入成功`，defId 版本递增、无唯一键冲突 |
| 2 | 流程关联表单表 | 设计器把三定义分别关联 `workflow_bill`(main_10/11/12)；发起一个实例 | `wf_instance.form_id` 正确、`data_id` 在对应 `formtable_main_NN` 建有行业务行 |
| 3 | 正文字段渲染与初始化 | 表单放 `htmlType=9` 正文字段；发起/办理页打开 | 正文控件渲染；首次打开自动 `POST /odoc/doc/init` 建正文并把 docId 回写表单字段 |
| 4 | 手动上传新版本 + 版本历史 + 回滚 | 上传 .docx（OSS put-file→fileId）→ `POST /odoc/doc/version/save`；查看 `/versions`；`/version/rollback` | 每次保存产新版本号；版本历史按号倒序；回滚克隆目标版本为新版本 |
| 5 | 在线编辑保存回调（需 DOCS） | 配 `odoc.doc-server-url/public-base-url/file-service-*`；点「在线编辑」保存 | OnlyOffice 回调 `POST /odoc/doc/callback`（status=2）落新版本；未配 DOCS 时 `canEdit=false`、仅上传/下载 |
| 6 | 智能排版 L1 | `GET /odoc/ai/layout?docTypeCode=TONGZHI`、`/ai/layout-rules` | 返回 GB/T 9704 版式（A4/边距/要素字体字号坐标）；规则展平可读 |
| 7 | 范文 | `GET /odoc/ai/samples?docTypeCode=QINGSHI` | 返回该文种范文 + 通用结构示例 |
| 8 | 敏感词扫描 | `POST /odoc/ai/sensitive-check?text=...` | 返回命中项（词/分类/下标）；无命中返回空 |

## 套红与文号

| # | 验收项 | 验收方法 | 通过标准 |
|---|---|---|---|
| 9 | 套红模板书签管理 | MouldManage 上传含书签 .docx → 「重新扫描」→ 标注正文占位 isContent →（或书签名=字段名免配）保存映射 | `extract-bookmarks` 列出书签；isContent/字段映射可保存回显 |
| 10 | 套红合成（正文插入 + 字段取自关联表） | 实例填好表单 → 正文控件选套红模板 → 「套红」 | 生成套红版 docx 新版本、`has_used_templet=1`；书签按「关联表单业务表当前行」取值填充（文号/标题等） |
| 11 | 取消套红 | 「取消套红」 | 克隆最近未套红版本为新版本、文档级 `has_used_templet=0`，历史可查 |
| 12 | 强制套红提交拦截 | 流程建文设置：套红节点 + `mustTaohong=1`；该节点未套红就提交 | `doApprove` 拒绝，前端收到「该节点提交前必须完成公文套红」；套红后放行 |
| 13 | 文号取号（并发不重号） | 建文号规则（prefix/年份/位数/补零、绑定 defId）；并发多次 `POST /odoc/number/assign?defId=` | 返回文号唯一、流水连续不重号（行锁原子自增）；`/preview` 不自增 |
| 14 | 定稿节点出口自动取号回写 | 流程建文设置 `finalizeNodeKey` + `numberFieldKey`；走流程到定稿节点提交 | 自动取号并回写业务表 `numberFieldKey`；重复提交幂等（已有值跳过） |

## 附：L2 叠加验收（采购厂商 SDK 后，见 `blade-workflow-odoc-layout/README.md`）

- 接入 SDK 并配 `odoc.layout.vendor` 后：`/odoc/layout/to`（12PDF/13OFD）产版式文件，前端 LayoutFileViewer 预览（PDF 原生 / OFD 阅读器）。
- 配 `odoc.seal.vendor` 后：`/odoc/seal/sign` 盖章 + RFC3161 时间戳落 `wf_odoc_seal`；`/odoc/seal/verify/{sealId}` 验章 + 篡改检测。
- OFD-A 归档：厂商 SDK 支持归档档级时在 `OfdVendorConvertor#toLayout` 按 format 细分实现（契约为字节进/字节出，已预留）。

## 验收通过判定

- 1–8、13、15 为 L1 必过项（开箱）。
- 9–12、14 在完成「流程关联表单 + 建文设置 + 套红模板」后必过。
- L2 附作项按采购情况验收；未采购时 15 的降级即为通过态。
