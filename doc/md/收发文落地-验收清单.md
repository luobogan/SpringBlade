# 收发文一体化落地 — 验收清单（15 项）

> 适用范围：SpringBlade 收发文（发文 / 收文 / 签报）全链路，L1 开箱可用、L2 配置叠加。
> 关联文档：《收发文一体化技术方案.md》《收发文落地-编辑器选型与套红合成设计.md》《收发文落地-版式文件OFD-PDF电子公文方案.md》。
> 联调方式：dev 环境用 springblade-dev-login 技能取 sword-token 调 `/blade-workflow/odoc/**`；前端 umi dev（8000）走 `/api` 代理。
> 清理：所有 `is_test=1` 测试数据须可一键清理，不污染正式数据。

约定：流程定义与表单表关联——集团公司发文→`formtable_main_10`、集团部门收文→`formtable_main_11`、集团收文→`formtable_main_12`。

## 附：L2 叠加验收（采购厂商 SDK 后，见 `blade-workflow-odoc-layout/README.md`）

- 接入 SDK 并配 `odoc.layout.vendor` 后：`/odoc/layout/to`（12PDF/13OFD）产版式文件，前端 LayoutFileViewer 预览（PDF 原生 / OFD 阅读器）。
- 配 `odoc.seal.vendor` 后：`/odoc/seal/sign` 盖章 + RFC3161 时间戳落 `wf_odoc_seal`；`/odoc/seal/verify/{sealId}` 验章 + 篡改检测。
- OFD-A 归档：厂商 SDK 支持归档档级时在 `OfdVendorConvertor#toLayout` 按 format 细分实现（契约为字节进/字节出，已预留）。
- **正文编辑器与 L2 无关**：OFD 输出走 `BuiltinOfdConvertor` / L2 厂商 SDK 的版式文件路线，不随编辑器选型改变；WPS Web 为 P0 已定稿的主编辑器。

## 附：WPS WebOffice 联调验收（P2.7 / P3.3 / P3.5，需人工）

> WPS 中台是外部依赖，自动化测试无法覆盖真实「发起编辑 → 三阶段保存 → 历史版本」全链路。以下为联调环境人工验收项，权威口径见《收发文落地-编辑器WPS统一改造方案.md》。

**前置**：① WPS 开放平台控制台登记的回调地址、appId 是否与知识管理同一套（人工确认）；② `blade.wps.app-id/app-secret` 已注入、`url-sign-secret` 两侧一致；③ `/v3/3rd/**` 网关白名单已开，且**已按 3.5 部署片段补路由或 nginx 改写**；④ `blade.wps.callback-auth-strict=true`（默认）。

| # | 验证点 | 操作 | 通过标准 |
|---|---|---|---|
| W1 | 网关可达 + 白名单 + 硬校验 | 不带 `Blade-Auth` 请求 `GET https://www.zwymding.top/v3/3rd/files/doc:1` | 返回 `40101`（token 缺失被硬校验拒绝）；若返回 401/404 说明白名单或路由未生效 |
| W2 | 初始化配置 | `POST /blade-workflow/odoc/doc/init?instanceId=&editor=wps` | `editorType=wps`、`wpsEditorConfig` 非 null 且含 `appId/fileId=odoc:{docId}/token/jssdkUrl/contentUrl` |
| W3 | 编辑器打开 | 正文卡片点「在线编辑」 | `WpsEditor` 加载 `WebOfficeSDK` 成功渲染，无「SDK 未加载」告警 |
| W4 | 编辑保存全链路 | 在 WPS 内改正文并保存 | WPS 中台三阶段（prepare/address/PUT）完成；`/odoc/wps/upload/odoc:{docId}` 落新版本，`getBusinessData` 无异常 |
| W5 | 版本链与内容 | `/odoc/doc/{docId}/versions`、下载新版本 | 版本号递增、按号倒序；下载字节与保存内容一致 |
| W6 | 套红 / 取消套红 | 编辑保存后执行套红、取消套红（第 10/11 项） | 正常生成/回退版本；⚠️ `hasUsedTemplet` 在 WPS 保存后是否重置（R6）需产品确认，当前实现为保留文档级套红态 |
| W7 | OnlyOffice 降级 | `init?editor=onlyoffice` 后点「在线编辑」 | `editorType=onlyoffice`、`editorConfig` 非 null，原 `DocsAPI.DocEditor` 可编辑保存 |
| W8 | 越权拒绝 | 伪造/过期 token、`doc` 域 fileId 打 odoc Provider | 分别返回 `40101` / `40005`，且不触达业务存储 |
| W9 | 密钥一致性 | 轮换 `appSecret` / `url-sign-secret` 后重启两服务 | doc 与 odoc 回调均验签通过；dev 未注入环境变量时 WPS 编辑应按预期不可用（`isConfigured()=false`） |

⚠️ **联调禁忌**：W1 若返回 `40101` 说明链路正确；若怀疑 WPS 中台未回传 `X-WebOffice-Token` 导致回调全挂，**不要**直接把 `callback-auth-strict` 设为 `false` —— 此时网关白名单已开，等于把 `/v3/3rd/**`（含 `objectPut` 写库端点）完全暴露。应先抓中台回调头确认，必要时同步移除白名单再排障。

## 验收通过判定

- 1–4、6–8、13、15 为 L1 必过项（开箱）。
- **第 5 项（WPS 在线编辑）依赖外部 WPS 中台**：未联调 WPS 时，以「`canEdit=false`、仅上传/下载」或 `editor=onlyoffice` 降级路径作为通过态；真实 WPS 全链路按下方 W1–W9 人工验收，不因自动化单测通过而视为完成。
- 9–12、14 在完成「流程关联表单 + 建文设置 + 套红模板」后必过。
- L2 附作项按采购情况验收；未采购时 15 的降级即为通过态。
